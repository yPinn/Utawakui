# Product

## Register

product

## Platform

web

## Users

Utawakui is for streamers, VTubers, and karaoke / cover-song performers who prepare and operate an OBS-adjacent singing workflow from a desktop control panel.

The primary user is the performer or stream operator working under live-session pressure: selecting tracks, checking lyrics, adjusting playback, and keeping the next action clear without distracting from the performance.

Secondary consumers are future OBS overlay viewers, but they do not operate the control panel. Overlay design should be treated as a separate public-output surface.

## Product Purpose

Utawakui exists to make karaoke / cover-song preparation and live operation calmer, more reliable, and easier to scan. It organizes local media, playlists, lyrics, playback, pitch/tempo controls, generated vocal-separation media, and future OBS overlay state in one coherent workflow.

Success means a user can prepare a session before going live, operate the queue during performance, recover from common missing-data states, and avoid guessing where a control or status lives.

## Positioning

Utawakui is a local-first OBS singing-session control panel: a focused production tool for managing prepared media, playback, lyrics, and overlay state without turning the interface into a media store or decorative dashboard.

## Brand Personality

Calm, deliberate, and operational.

The product should feel like a dependable live-production surface: composed, legible, and quietly capable. It should not chase novelty while a performer is trying to stay in rhythm.

The visual identity is not finalized yet. Future style exploration should define the final atmosphere, but it must preserve live-use clarity and product trust.

## Anti-references

Utawakui should not look or behave like:

- A SaaS marketing dashboard with oversized hero metrics.
- A generic AI-tool dark UI with purple gradients, glow, and glass effects.
- A playful fan skin where decoration competes with live controls.
- A media-store landing page that treats acquisition as the core story.
- A dense engineering console that exposes implementation details to the performer.

## Design Principles

1. **Live clarity first.** Every screen should make the next useful action easy to find during a session.
2. **Operational density without clutter.** The UI can be information-rich, but hierarchy and spacing must keep it scannable.
3. **Local-first mental model.** Library, playlists, playback, lyrics, processing, and provider flows should remain clearly separated.
4. **Familiar controls win.** Use standard product UI patterns unless a custom interaction materially improves live operation.
5. **Overlay is a separate surface.** Control-panel design and OBS overlay design may share product language, but not token assumptions.

## Accessibility & Inclusion

Baseline target: accessible product UI with keyboard support, visible focus, sufficient contrast, reduced-motion handling, and text layouts that tolerate Japanese, Korean, Traditional Chinese, and English metadata.

Touch and responsive sizing should borrow safe-area and target-size conventions from iOS and Android where useful, but the default platform remains web.
