## CPU 多段一致歌詞 offset 建議：最小方案

日期：2026-10-22。狀態為規劃，尚未實作或實測。保留 HubertFA＋small CPU、現有模型／環境及原內容門檻；本輪只有文件與證據盤點，沒有推論、下載、修改人工 offset、T2、估計或人工驗收結果。新增 GPU 與 VAD 接入均不包含在本方案。

### 目標與停止邊界

目標是判斷同一份歌詞相對同一錄音，是否有多段一致的小幅整體偏移，先產生可撤回的研究建議。不是逐詞重對齊、錯版本修復或自動校時；未經另行決定，不接產品、不新增設定或套用按鈕。

| 情況                             | 本方案處理                                |
| -------------------------------- | ----------------------------------------- |
| 多段有一致小幅提早／落後         | 可列校時候選，仍待人工確認                |
| 單句錯時、漏詞或重複段配錯       | 不用全曲 offset 補救                      |
| 前後偏差逐漸變大、剪接／版本不同 | 不建議單一 offset；記錄不一致或內容問題   |
| 顯示採樣、輸出或硬體播放延遲     | 不改歌曲 offset；與顯示時鐘／硬體驗收分開 |
| T1 本來刻意提前提示              | 差值不等於錯誤；保留使用者的提詞習慣      |

第一版僅規劃純 T1、可分流的單語中／日／英句；含原生或人工 T2 的來源整份先保護，不因部分 T1 的建議移動已可用 T2。句內混語、無整句時間、超過既有 20 秒單句限制、未知發音及不足內容證據均不擴充。零 offset 不代表未經人工調整；任何現值都只讀快照，不自動覆蓋。

### 已有證據能支持到哪裡

目前逐句分流、CPU 對齊、盲內容查核與 offset 只換算一次已有實作／回歸證據，方法見[逐句紀錄](../research/lyrics-alignment/lyrics-mixed-cpu-feasibility-2026-10-21.md)。這不能直接證明能估出整曲 offset。

本輪唯讀核對的正常配對資料為中／日各兩份 30 秒裁片，共 29 句；GPU 對照另有一份 169 秒英文錄音，但只保存一個指定行的對照結果。同份錄音中的多句可用來研究局部一致性，不能冒充整首前、中、後都有證據。其他歷史 ASR／全曲研究未在本輪核對成可直接合併的相同配方，不以「曾跑過整曲」補足缺口。

後續[既有快取盤點](../research/lyrics-alignment/lyrics-offset-cache-audit-2026-10-22.md)確認四首舊全曲的音訊／來源／offset 與 33 窗 small 轉錄可核對，但 HubertFA 只保存發布詞塊，缺原始首詞。四份短裁片雖保有 25 句 raw 首詞，全部在原曲前段，舊內容狀態均為 unknown；目前沒有同曲六句完整聯合證據，缺測不補跑。

[細時間研究](../research/lyrics-alignment/lyrics-fine-timing-clock-2026-10-22.md)保留原始詞／音素觀測，可能供盤點使用；已發布 chunks 的第一塊沿用 T1 起點，fine 映射也可能過濾跨框資料。只讀原始、來源與時計完整的觀測，不由這兩種過濾後資料反推第一個發聲。該研究的合法時間、provider 代理及模型一致都不是人工真值。

既有[guide 配對](../research/lyrics-alignment/lyrics-model-pairing-2026-10-19.md)沒有支持把 guide 同送 ASR 作預設。最小方案仍用原混音；沒有 guide 不做新分離，也不混用不同錄音版本。VAD 硬篩選的已知誤拒另見[活動研究](../research/lyrics-alignment/lyrics-qwen-quality-2026-10-19.md)，不重做該路徑。

### 正負方向與錨點定義

沿用[聲學估計契約](../contracts/lyrics-acoustic-estimate-contract.md)：

```text
歌詞位置 = 音訊位置 + 目前 offset
s_i       = 來源 T1 該行起點（歌詞時計）
a_i       = 模型觀測該行第一個實際詞起音（原始音訊時計）
o_i       = s_i - a_i                  # 對齊該發聲的絕對 offset 候選
delta_i   = o_i - o_0                  # 相對目前 offset 的建議改變
o_proposed = o_0 + median(delta_fit)
```

`a_i` 必須是 decoder 原始第一個詞 occurrence（index 0）的起音，加上原窗在音訊中的開始位置；不再加 `o_0`。首詞缺失就沒有錨點，不能拿第一個有回傳的後續詞替代。若只剩已換算到歌詞時計的完整原始模型起音，須依其收據先減回同一個 `o_0`；時計未知就拒用，不能猜。正 delta 代表相對目前提前顯示歌詞，負 delta 代表延後。

原始時間與 delta 先保留其解析度檢查條件，候選最後才四捨五入成整數毫秒；顯示毫秒不表示毫秒級準確。候選仍受原來源 offset 的 ±3,600,000 ms 上限約束，超出拒絕，不 clamp 成合法值。

例如來源起點 10,000 ms、原音訊觀測 9,900 ms、目前 offset 0，候選為 +100 ms。若目前 +300 ms，來源起點 10,000 ms、觀測 9,800 ms，絕對候選為 +200 ms，相對變化是 −100 ms；不是再加一次 +200 ms。這些只是方向算例，沒有真實音訊驗收結論。

T1 沒有原生內部詞時間，不能把字數均分、BPM、下一詞或句尾當內部參考。每行只提供一個首詞錨點，不能以同句十個模型詞當十張獨立票。原始首詞也受 T1 行框前後 350 ms 解碼約束，靠近裁框邊緣的觀測會有偏誤；沒有觀測到大位移不代表大位移不存在。

### 最小資料與候選流程

1. 只盤點既有快取：綁定同錄音 audio SHA、同來源 SHA／canonical occurrence、當前 offset 快照、模型／字典／decoder 配方、窗位置及原始首詞。原始資料缺少、版本不相容或只有顯示 chunks 時列缺證據，不補造。不同配方不混票；已有等價性觀測須另附收據。
2. 歌曲按原音訊長度分前、中、後三段，不新增段落模型。每段預先選兩句，共六個固定目標；只依文字／原始時序與現有可處理範圍選取，避開無法唯一定位的重複句。選後凍結，不因結果不好換句，六個目標均留在分母。任一段不足兩句就只報資料不足，短裁片不能作整曲建議。
3. 原混音 small 盲內容結果須支持各目標且能對應同一 occurrence；不提供歌詞 prompt、不放寬原門檻、不反覆改語言挑結果。明確矛盾或未知／漏轉錄都不能提供正面 offset 支持。來源主要語言或音素合法本身不算內容證據。
4. 使用相同配方的 HubertFA 原始首詞觀測產生六個 `delta_i`。每段第一句只供擬合、第二句只供留出檢查；三句擬合的 median 形成一個候選，其餘三句不參與選值。多句仍共享模型偏差，留出檢查不是獨立人工真值。
5. 全部條件滿足才列候選；否則記錄資料不足、不一致、超範圍或無需微調。報告同時列六個目標、缺測／內容拒絕、逐段 delta、散布及留出殘差，不只列 median。T1 可能有刻意提前量，因此即使一致也不自動判為「原歌詞錯了」。

以下為提議的首輪保守研究參數，尚未校準或啟用；必須在看新結果前固定，不能為通過調大容忍。它們不修改現有內容門檻，也不是正式產品 gate：

| 項目       | 提議規則                                                                  |
| ---------- | ------------------------------------------------------------------------- |
| 有效資料   | 固定六句全有原始首詞與內容支持，三段各兩句；缺一項即不產生整曲候選        |
| 小幅範圍   | 每個 delta 限 ±200 ms；超出只報超範圍，不擴框／多 offset 重跑             |
| 裁框保護   | 首詞離 decoder 裁框兩端均至少 100 ms，否則不作 offset 錨點                |
| 不追小誤差 | 擬合 median 絕對值 <100 ms 時報「不建議微調」；不承諾修準幾十毫秒         |
| 一致性     | 六句方向相同；每句距擬合 median ≤100 ms；三段各自 median 的最大差 ≤100 ms |
| 留出檢查   | 三句留出均通過上列條件；不能事後刪掉失敗留出點再發布                      |
| 既有人工值 | 顯示目前值、絕對候選及相對 delta，人工值完全不寫入                        |

不一致時先保留原值，不擬合線性漂移、不產生分段 offset 或改句框。這些是另外的能力，不納入本次最小方案。

### 有界驗證方式

本輪只提出下列驗證，不執行演算法或模型。後續若另行授權，先以固定快取／合成時計驗證，再決定是否需要少量新 CPU 推論。

| 層次             | 固定案例與檢查                                             | 能證明／不能證明                                                        |
| ---------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------- |
| 時計算術         | 0、±100、±200 ms；目前 offset 為正、負或零；窗起點非零     | 正負與只換算一次；不證明聲學準確                                        |
| 同錄音快取反事實 | 對同份凍結來源時間加已知常數，保留原音訊時計與原始觀測     | 聚合方向／穩定性；不能當已重跑受改動行框影響的模型，不回填原 cache 身分 |
| 不應建議控制     | 零偏移、單句跳時、前後漸增漂移、少一段、矛盾方向或貼裁框   | 必須 no-change 或不足／不一致；失敗不刪分母                             |
| 內容與定位       | 錯版本、重複副歌、漏詞、混語、未知發音、近數位靜音         | 沿原內容／支援規則回退；不能靠一致時間接受錯文字                        |
| 來源保護         | 原生／人工 T2、非零人工 offset、來源／音訊變更、舊配方     | 不提自動寫入；舊身分不可借用，stale 即停止                              |
| 有界自然抽查     | 最多兩首既有錄音，中／日各一；每首固定六句／三段           | 只有快取齊全才離線評估；少資料保留缺測，不換歌找成功例                  |
| 人工時間         | 上述自然目標需本人核對發聲與原先提前提示意圖，先隱藏候選   | 人工未確認保持 pending、時間準確率 null；模型共識及 provider 不代填     |
| 未來接入前才驗   | 取消／失敗、來源變更競態、無建議、手動套用／撤回及估計失效 | 本方案尚無產品路徑；現有取消測試不能冒稱新流程驗收完成                  |

如果兩首均缺三段相容快取，第一輪結論就是「現有證據不足以驗證整曲 offset」，不啟動推論。若未來另授權補證據，最多規劃 12 個不重疊／可去重的既有上限 30 秒聲學窗，以及最多 12 次原 CPU small 工作；不反覆掃位移、不改權重或環境。實際耗時／RAM 未量，不報 ETA 或加速倍率。

後續評估須同列：固定目標與缺測、自然案例有無建議、正負方向／留出殘差、內容誤接受與正常誤拒、人工差異及額外工作成本。只改時間的合成控制不能替代自然已知偏移；同一來源改五個常數不是五首歌。

最小研究輸出只是一份來源綁定報告：目前 offset、候選絕對 offset／相對 delta 或空值、六句錨點與拒用原因、前中後覆蓋、擬合／留出角色、殘差、資產／配方 hashes，以及獨立的人工 pending 狀態。沒有 candidate 不偽造 0；沒有人工起音不報準確率。

## 純 T1 中文單曲：六句 offset 缺測補齊計畫

日期：2026-10-22。僅規劃，尚未執行內容重判、模型、音訊解碼或 offset 估計。沿用現有 HubertFA＋small CPU 環境，不下載、不安裝、不改來源／人工 offset、不接產品、不 commit。承接[快取盤點](../research/lyrics-alignment/lyrics-offset-cache-audit-2026-10-22.md)與[候選規則](#cpu-多段一致歌詞-offset-建議最小方案)。

### 單曲與固定六句

### 可沿用與需補跑

沿既有 2 秒前後 context、最多 30 秒聲學窗規劃；decoder 每句仍為原 T1 行框前後 350 ms，不為估 offset 掃描多個位置。

| 窗口 | 原音訊範圍（秒） | 固定目標   | 預計工作                                                         |
| ---- | ---------------- | ---------- | ---------------------------------------------------------------- |
| W0   | 16.180–46.180    | O1、O2     | 優先重用原始首詞與盲 ASR，只做離線身分／內容重判                 |
| W1   | 93.360–123.360   | O3、O4、O5 | 新 small 1 次；內容足夠後新 HubertFA 前端 1 次、逐句 decode 3 次 |
| W2   | 116.990–146.990  | O6         | 新 small 1 次；內容足夠後新 HubertFA 前端 1 次、逐句 decode 1 次 |

W1 跨中後段，W1／W2 有重疊是既有窗口規劃的結果；目標分類仍按原錄音三等分。O5 只使用 W1 的轉錄／觀測，O6 只使用 W2；不從重疊窗口挑較容易通過的結果，也不把同一句重複算票。

- W0 HubertFA：沿用細時間研究的原始 request／response index 0 與 stock decoder 起點相等收據。原窗時計加回裁片原點 16,180 ms；不拿已發布首塊或 fine 過濾結果重建。
- W0 small：固定採用新曲研究 `small/results.json` 所指的 raw JSON，已有原始 raw SHA，以及音訊／來源／offset sidecar。原始 raw SHA 本輪核對相符；既有兩份 small 資產清單的 filename／bytes／SHA 相同，兩個 CLI 檔案 SHA 也相同。GPU 對照輸出只作成本參考，不因其內容結果較好而切換 raw。
- 舊 `unknown`、`reject: false` 或 `contentAccepted` 不直接採為支持。後續須用固定的現行內容與 token-clock 配方重新判讀 W0 原始盲轉錄，綁定原錄音／來源 occurrence。這是離線重判，沒有 ASR 推論。
- 目前工作目錄的 decoder／job 有並行變更，不能直接混入。已有原 decoder／protocol 的固定快照與觀測 decoder；後續先核對前處理、字典、prepared words、frame clock、350 ms 框與模型等價收據，再決定能否重用 W0。相同模型名或權重本身不足以證明相容。

一般支線只新增 2 個 HubertFA 窗、4 次逐句 decode、2 個 small 窗；兩窗各 30 秒，按窗合計 60 秒，因重疊而不是 60 秒不同音訊，HubertFA 與 small 各處理這兩窗。不是再分析整首。若 W0 的配方／證據身分無法確認，先回報並停止；另列上限支線為前段也重算，合計最多 3 窗 HubertFA／6 次 decode／3 窗 small，不自動採取此支線或另找歌曲。單純內容不支持不能藉重跑 W0 挑結果。

### 後續執行順序與停止條件

1. 先核對原錄音、來源、manifest／offset、既有環境及固定 recipe；來源出現 T2、SHA／offset 改動或配方不相容即停止，不換來源或調 offset。環境只讀，不修復、升級或自動補下載。
2. 離線重判固定 W0 的 O1／O2。若不足、矛盾、漏詞疑慮或 occurrence 無法唯一確認，保留六列與缺測理由，停止，不啟動新模型。不得依已知舊分數換成其他前段句。
3. W0 足夠才逐一執行 W1／W2 的 small 盲轉錄：中文、4 threads、`--no-gpu`、`--no-flash-attn`，不提供預期歌詞，維持中日整窗查核。任何目標缺少明確支持或有定位歧義就停止；其餘未跑項記未完成，不算成功。
4. 六句內容均足夠才補 W1／W2 HubertFA，使用同一 CPU session 的正常有界工作，不另做冷暖重跑。保存完整原始 spans（含 index 0）、prepared words、窗口位置、實際 begin／end、置信度、資產／程式／輸入 SHA 與成本。第一詞缺失不得拿後續詞代替。
5. 六點全齊才做離線候選分析：O1／O3／O5 擬合，O2／O4／O6 留出。沿原方案固定 ±200 ms、距裁框至少 100 ms、低於 100 ms 不微調、每點與跨段差 100 ms 等研究規則；不隨結果調參，不改產品內容 gate。缺任一點就沒有整曲候選；不要把沒有候選填成 0。
6. 人工另建六點 pending 清單，先隱藏模型時間聽原錄音，再比較首詞、偏移方向與 T1 是否刻意提前提示。先前其他歌曲的連音／接近等回饋不移植為這六點的通過。未經本人確認，人工起音／準確率保持空值。

新工作全部循序執行，不跟 OBS 或其他重型研究同時搶資源；有取消立即終止，不當成失敗後重跑。模型階段規劃整批 180 秒停止上限，所有失敗與未完項保留，無自動重試、擴窗或全曲掃描。此時尚無產品路徑，不以舊取消測試聲稱新 runner 已驗收。

## 歌詞內容與時間證據分離：最小研究方案

日期：2026-10-22。本頁保留驗證前的最小研究方案，承接[前段重判](../research/lyrics-alignment/lyrics-offset-zh-front-cache-check-2026-10-22.md)及[固定六句計畫](#純-t1-中文單曲六句-offset-缺測補齊計畫)。沿用既有 CPU 模型／環境與固定快取；產品 gate 與現有回退不變。

後續已完成[固定快取最小離線驗證](../research/lyrics-alignment/lyrics-content-time-offline-validation-2026-10-22.md)：O1 的整段文字支持與時間／位置限制可以分開說明，但沒有任何可校時目標；重複句 raw 缺測、漏詞排除仍不足。只建立 ignored 研究 adapter，未改產品、模型、環境或 offset，人工時間仍 pending，原停止結論保留。本輪研究階段結案；下列原方案不表示待自動補跑的工作。

### 問題與最小邊界

目前 `checkContent` 先依 ASR token 起點是否落在來源句框前後 500 ms 篩文字，再計算內容支持；`assessCompleteness` 的漏詞查核也使用此時間篩選。後續 O1 唯讀診斷確認：同一份轉錄其實有前三字，因 token 時間在左界外而未計入；另有一字替換。文字層為 13／14，既有篩選為 10／14，UTF-8、NFKC 與繁簡沒有造成差距。這些是既有診斷，不是本方案的新測試結果。

目標是讓「內容不足」與「ASR 詞時間不一致」各自說明原因，避免用 ASR 詞時間決定已辨出的文字是否存在。只新增研究報告的獨立證據欄位；不把 O1 改判通過，不恢復中後段補測，也不新增產品套用行為。

### 分開保存，保守合併

| 證據     | 提議判定依據                                                       | 不足時處理                                      |
| -------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| 文字內容 | 固定盲 ASR 片段的完整文字，沿既有正規化、覆蓋與矛盾規則比對        | insufficient／contradiction，不能靠聲學時間救援 |
| 出現位置 | 來源 occurrence、ASR segment／文字範圍、原窗口、鄰句順序與唯一對應 | ambiguous／unverified；文字高相似也不可校時     |
| 聲學時間 | HubertFA 原始 index 0 首詞、原窗口與配方、裁框及既有研究限制       | missing／unsafe；文字支持不補造時間             |

另保留舊 `evidenceState`、漏詞警示與 ASR token 時計診斷。ASR 詞時間有偏差時，只影響其時間可信度欄位，不刪除合法轉錄文字；非法 raw、超預算、來源／時鐘身分不明仍阻擋整份證據，不能藉文字欄掩蓋。

原則是所有必要證據同時成立：內容支持、出現位置唯一、缺詞防護符合原研究要求、聲學時間可用，才可能進入原六句 offset 一致性檢查。任何一項未知或不符，就保留原值與 T1 回退。人工時間仍 pending，不由這些欄位代填；有研究候選也不代表人工驗收通過。

### 固定文字範圍與防護

1. 先固定同一錄音／來源／offset／raw SHA／模型配方與原有最多 30 秒窗口，保留原文及 UTF-16 範圍。不擴音訊窗、不換轉錄、不搜尋整曲其他位置補字、不使用預期歌詞 prompt。
2. 第一版只研究「一個完整 ASR segment 對一個完整來源句」。比較整段文字，保留額外字與替換，不用最佳子字串裁掉不合內容。以窗口內原來源句與 ASR segment 的順序建立單調、一對一對應；在原支持門檻下若有多種可行對應，就記 ambiguous，不選最高分那條。相鄰句可核對時一併檢查順序；缺少必要定位脈絡就 unverified。原曲首尾沒有鄰句時只記已知來源邊界，不捏造錨點。
3. 同時檢查整份來源的重複正文，以及固定窗口內的重複 ASR 片段／匹配路徑。來源文字唯一只是必要線索，不能單憑此宣稱音訊 occurrence 唯一。ASR 合併多句、拆成多段、跨句或有無法分配的鄰句內容，第一版保留未知；不按字數拆、不內插或靠 token 時間強分配。不完整的窗口邊緣片段也不能當完整句支持。
4. ASR segment 的時間只核對與原窗口的合法身分；不用其首字距 T1 起點多近來決定文字支持。ASR token 時間仍完整保存作差異診斷，但不作本方案的聲學起音，也不與 HubertFA 起點平均。
5. 數值門檻原樣保留：中文至少 4 個有效字元且覆蓋 ≥0.8 才能支持；至少 4 字且覆蓋 ≤0.2 的明確矛盾繼續阻擋。既有額外文字警示的至少 3 字／比例 ≥0.35，以及插入查核的雙側各 2 字唯一錨點、2–8 字範圍均保留。繁簡／NFKC 只供比較，不新增同音替換、模糊修詞或外語刪除。
6. 原時間篩選結果不被覆寫：明確 contradiction、近數位靜音拒絕及既有漏詞警示不得被新的文字相似度救回。新舊結果不取最高分、不採任一支持即可通過。原為 insufficient 時，新文字結果最多提供一份獨立內容支持；還須通過上述定位、防護與聲學條件。

漏詞查核須使用同一個已唯一分配的完整 ASR segment，不能先把多出的字裁掉。沿用插入警示與歧義規則，沒有觸發警示不等於「沒有漏詞」；遇到無法唯一比較、替換遮住錨點或證據不足，保留 unknown，不填 clear。若原 offset 研究要求排除缺詞疑慮，此處 unknown 仍停止，不能因文字覆蓋高就放行。

現行插入查核在未觸發時通常也只回傳 unknown，本方案不新增「已排除漏詞」的證明。第一階段因此可能只改善原因分類，仍無法產生 offset 候選；是否容許這類 unknown 進入自動候選，需要另行決策與驗證，不包含在本輪。

這是改變證據的使用方式，須視為新研究配方；數值不變並不能自行證明誤接受風險不變，必須先驗證負例。舊分母、失敗與停止結果保留，不重寫歷史數字。

### O1 的預期呈現與未決項

O1 可呈現「文字相似度已有支持線索」「ASR token 時間與來源句框不一致」「出現位置／聲學可用性／缺詞疑慮仍分別待核」。13／14 只來自既有文字診斷，尚未按本方案完成片段分配與防護，不能宣布新 contentState 已通過。

其末字替換不會被繁簡或同音規則消除。新方案若只能改善說明而仍無法滿足校時條件，結論仍是不能校時。保留 HubertFA 的原始時間與裁框保護，不移動 offset 讓 ASR 時間看起來相符。

後續另獲授權後，僅以固定 O1／O2、既有錯段／刪詞／重複句快取及少量標記為合成的資料副本驗證；原始證據不修改。沒有對應 raw 或人工標記就列缺測，不重新推論。以下只列驗證要求，本輪未執行：

| 固定組別                         | 必須檢查的行為                                                                                                   |

| 合法 ASR 詞時間偏移副本          | raw 文字／segment／窗口身分不變且時計仍合法時，文字與序列對應不因 token 跨 T1 篩選界限改變；只變時間診斷         |
