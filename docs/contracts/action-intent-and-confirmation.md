# 操作層級、破壞性意圖與確認

variant 表達局部主次，intent 表達損失；不能只依「刪除」、「清除」、「停止」等字樣分類。
Accent 用於局部主要操作，Secondary 用於次要決策及一般服務停止，Ghost 用於工具列／選單入口與重複操作。
Danger 與這些層級獨立：破壞性入口通常為 Ghost／Overlay／選單 danger，最終確認為 Accent／danger，取消為 Secondary／neutral。

## 各流程的判定

| 流程                                     | 意圖與確認                                    | 邊界                                                                       |
| ---------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| 曲庫刪除曲目                             | Danger；共用確認                              | 刪除音檔、去人聲版本及各清單引用，無法復原。                               |
| 刪除播放清單／移除專輯                   | Danger；共用確認                              | 刪除集合資料，曲庫音檔保留。                                               |
| 從播放清單移除曲目                       | Danger；共用確認                              | 修改已儲存的清單安排；確認指出目標清單及音檔保留。來源專輯不提供成員編輯。 |
| 播放清單移除封面                         | Overlay／danger；共用確認                     | 封面立即寫入，不能以名稱表單的取消恢復；等待確認期間沿用 saving 鎖。       |
| 移除藝人照片                             | 選單 danger；共用確認                         | 立即移除目前照片；曲目與藝人資料保留。                                     |
| 頁面照片／便條                           | Danger；原確認 owner                          | 照片移除保留原檔，便條刪除無法復原；閱讀視窗與頁面選單均走原確認。         |
| 歌曲編輯器移除封面                       | Ghost／neutral；無即時刪除確認                | 只改 artworkDraft；取消編輯可還原，按儲存才提交。                          |
| 刪除歌詞來源                             | Danger；列內二階確認                          | pendingDeleteSource 保留來源身分；取消不刪除，執行中禁止重複提交。         |
| 待唱安排移除／清除／取代                 | Danger；共用確認                              | 已儲存的項目與手動調整會遺失，曲庫與播放清單保留。                         |
| 分析標註合併上段                         | Ghost／danger；共用確認                       | 移除邊界；角色不同時清除角色標註，而且會自動儲存。                         |
| 更換標註工作集                           | 有未儲存變更時才是 danger，沿用原確認         | 沒有待儲存變更時為一般開啟／更換操作。                                     |
| 分析選取、節拍點擊記錄、播放佇列清空     | Neutral；直接執行                             | 操作暫存選取／執行狀態，不刪除曲庫、清單或分析檔案。                       |
| 匯入／分離停止、移除待處理或清除完成紀錄 | Ghost／neutral；直接執行                      | 取消工作或移除工作列項目，不刪除既有歌曲與分離版本。                       |
| Output／OBS 啟停                         | 啟動 Accent／neutral；停止 Secondary／neutral | 可重新啟動；不因停止而套用資料刪除確認。                                   |
| 常用色票、數值重設                       | Neutral；直接執行                             | 已知值可重新設定，色票可立即加回。                                         |
| 藝人合併／拆分                           | Neutral；保留既有確認                         | 可復原上一次整理；不改寫原曲目標示。與丟失標註的段落合併不同。             |
| 關窗時停止處理並結束                     | Danger；原關窗決策                            | 原決策視窗已明示終止處理，不再疊加第二個確認。                             |
| BGM Emergency Cut                        | Ghost／danger；立即執行                       | 既有緊急操作例外，詳見 BGM 契約；不得加上會延遲切斷的確認。                |

設定頁的清除紀錄、清理版本、密碼與工具移除另見 [Settings 操作回饋契約](settings-operation-feedback.md)。
BGM 例外見 [BGM 待機播放契約](bgm-standby-lane.md)，不得由一般停止服務規則推翻。

## 確認與晚到回應

- 確認屬於原 feature／action owner，不移入通用按鈕或底層 IPC wrapper。
- 取消不得呼叫寫入；確認後只呼叫一次。確認視窗不預設聚焦 danger 按鈕。
- 等待確認時記錄目標身分與內容。新的封面／照片、不同案例或不同標註不能被舊確認移除。
- 標註比較實際案例與段落內容，不比較物件參考；正常 autosave 回傳相同內容的新物件仍可繼續操作。
- 清單成員移除失敗不清除目前選取；離開原清單後不清除其他頁面選取。
- 封面確認取消後保留名稱／說明草稿，名稱表單的取消不代表撤回已確認的即時封面操作。

## 驗證

`UiButton.destructive-consumers.test.js` 驗證正式 UiButton／UiIconButton 的 intent、確認 owner、危險選單及中性例外。
`usePlaylistActions.test.js` 驗證即時封面確認、取消、防重、saving 解鎖與晚到封面。
`LibraryBrowseContent.destructive-actions.test.js` 驗證照片與清單成員的確認／取消、唯讀專輯及晚到目標。
`MusicAnalysisReferenceAnnotation.actions.test.js` 驗證合併取消、案例／角色變更與相同 autosave snapshot。
可見隔離 Electron 以正式 modal／menu／編輯器、原共用確認 owner 與 fake bridge 驗證堆疊、草稿保留及單次操作；
來源擷取的頁面 handler 與正式元件組合是功能檢查，不代表已在使用者實際曲庫進行刪除驗收。
