# Settings 操作回饋契約

## Ownership

`App.vue` 在頁面切換之外掛載單一 `AppNotificationHost`，使用 app-shell 的 registered overlay host。
`useAppNotifications` 只保存公開通知投影與私有 action callback，不持有 domain 任務、設定或 IPC 權威。
`UiNotificationHost` 負責最多三筆可見項目的排列、計時、hover／focus 暫停與關閉；隱藏項目尚未開始倒數。
通知同一 operation key 的更新會替換舊 item，並建立新 id；舊 callback、過期的關閉與重試事件不能影響新通知。
通知依結果／失敗／進度的 priority 排列，同優先權維持先到順序；長任務沿用第三期的同 id 投影。
Shell 既有的表演者畫面錯誤也由同一通知 owner 呈現，不再維護另一個相同位置的固定浮層。
通知 item 使用正式不透明 surface 承接半透明 semantic Notice 背景，避免底下的操作內容透出干擾閱讀。
一般進出場只使用位移，item 的 opacity 全程維持 1；離場以原本距離 shelf 底部的布局位置固定，避免 bottom-anchored shelf 收縮時把通知推入播放列。
App adapter 明確傳入既有 Dock owner 的目前寬度（224–280px），Dock 收合時仍保留這個可讀寬度；不依賴 Teleport 的 attrs fallthrough 或區域 CSS 變數繼承。
UI host 保留 viewport 安全邊界，其他 caller 可沿用原本的通用預設尺寸。高度由內容決定，窄於 20rem 的通知將 action 排到文字下方，不固定高度或截斷恢復操作。

## 第一期適用範圍

| 操作                       | 結果呈現                                             | 頁內保留                                       |
| -------------------------- | ---------------------------------------------------- | ---------------------------------------------- |
| 診斷清除／匯出             | 成功短暫通知、失敗可關閉通知；取消另存不通知         | 紀錄數量、獨立的讀取錯誤                       |
| 診斷資料夾開啟             | 失敗通知，可重試同一操作                             | 紀錄讀取狀態                                   |
| 最近播放清除               | 成功／失敗通知                                       | 數量、讀取／更新錯誤                           |
| 去人聲空間清理             | 本次釋放量或不需清理的短暫通知、失敗通知             | 即時容量、政策、獨立讀取／儲存錯誤、操作中提示 |
| 曲庫資料夾選擇／還原／開啟 | 設定頁發起時，失敗通知附同一操作重試；成功直接更新值 | 路徑、磁碟可用性與設定讀取錯誤                 |

成功通知預設六秒後關閉，失敗保留至關閉、同操作結果替換或恢復。
通知 action 先消耗原 item，再執行 callback；callback 新發出的結果不會被舊通知清除。
清除診斷、播放紀錄與去人聲版本仍由設定區段呼叫原確認流程；失敗通知不提供略過確認的破壞性重試。
匯出／資料夾的非破壞性重試執行原 operation，不重做不相干的刷新或其他動作。

## 事件與狀態

- 通知由本次 operation 結果發送，不 watch 舊 notice／cleanup snapshot；切頁與刷新不重播完成訊息。
- 診斷讀取失敗與清除／匯出／開資料夾結果分開；匯出成功不能清掉讀取故障。
- 清理操作失敗不覆寫空間的讀取／政策錯誤；歷史 cleanup snapshot 不產生完成通知。
- 曲庫資料夾操作以 `notifyFailure` 選擇回饋目的地；設定頁使用通知，既有匯入入口維持原狀態出口，避免設定操作覆寫匯入進度。
- `configError` 由曲庫設定讀取結果驅動，失敗留頁內、成功清除；設定初始化不依賴一個接不到內部 catch 的外層例外處理。
- 公開通知文字由固定產品文案與 bounded 數量／容量構成，不傳送原始例外、私有路徑或後端回應。未預期的 action 例外沿 renderer diagnostics 記錄並顯示固定公開訊息。

## 第二期：設定旁的錯誤

欄位驗證、讀取失敗、儲存／管理操作失敗及服務持續故障各自保存，不以單一錯誤字串互相覆蓋。一般設定讀寫留在所屬欄位；第三期長任務另有一次完成／失敗通知，頁內錯誤仍供返回設定時處理。

- OBS 主機、連接埠、密碼長度與略過門檻使用各自的 `UiField` error，保留原生 `aria-invalid`／`aria-describedby`。提交時開啟設定並聚焦第一個錯誤；編輯時只更新欄位提示，不反覆移動焦點。連線故障留在連線列，可與無效草稿同時顯示；設定讀取、儲存與密碼移除失敗分開。
- Windows 關閉行為、GPU 加速、自動 BPM 分析與更新自動檢查共用 `useSettingsPreference` 的讀寫邊界。初次讀取未確認時停用選項並標明狀態；讀取失敗提供本列重讀。儲存失敗回復原值，後續背景讀取不能清除該失敗。寫入可取代舊讀取，舊回應不得覆寫新值。
- 元件／工具的管理錯誤以 dependency id 歸位，讀取失敗另留在功能狀態入口。重新讀取或其他工具成功不清除失敗項目；修復重試執行修復，移除沿用原確認入口。啟用確認錯誤只在原確認視窗顯示；設定頁另外顯示功能狀態的讀取失敗。
- Output 設定只讀取服務、設定讀寫與啟停的錯誤；工作台版面／色票等錯誤不流入設定列。連接埠衝突與建議位置靠近連接埠，合法負畫面延遲保留。服務狀態與失敗草稿分開，狀態讀取失敗不顯示成已停止。
- Spout2 狀態讀取、幀率儲存與啟停失敗分開；正常狀態讀取不清除幀率儲存失敗。持續故障原因在 Spout2 設定旁顯示一次。
- 曲庫空間讀取與政策儲存錯誤分開，讀取成功不能清除失敗的政策變更；清理結果延續第一期通知。

`SettingsDocumentItem` 的 feedback slot 承載該列的讀取／操作回饋，欄位本身的錯誤仍交由欄位 primitive。既有處理進度與跨頁長任務生命週期不在本期變更範圍。

## 第三期：跨頁任務與附屬彈窗

更新下載、dependency 的準備／修復／移除、BPM 元件管理由原 domain owner 執行。
`useTaskNotification` 只建立該次操作的通知投影 handle；主程序／domain 的 busy、回應與進度事件仍是執行權威。
同一次操作以同 id 更新階段、可用百分比與結果；進度不倒數，完成改為短暫通知，失敗持續並提供相同 operation 重試。
未知百分比使用原生不定進度，不假造百分比。一般進度更新不反覆向讀屏播報，開始／完成／失敗仍禮貌宣告。

- 關閉進度通知只隱藏投影，不取消任務，也不在後續進度事件重建通知；結束可提醒一次。新 attempt 的投影 identity 會使舊回應失效，即使新結果已關閉，舊 attempt 也不能重現。
- 通知結果優先於長進度；重大失敗高於一般結果，避免三個長任務占滿 shelf。其他同優先權通知維持先到順序。
- 進度通知的「查看設定」不消耗通知；完成更新只提供「查看更新」，下載完成不自動安裝，重新啟動與安裝仍由版本列明確操作。重複或過期狀態不重播完成；晚到 RPC 回應不能把較新的推送降回下載中。
- dependency 以 id 鎖定 renderer 操作，準備與修復／移除不交錯執行同一元件；不同元件可各自回饋。移除失敗的通知回設定，原確認流程保留；修復重試不誤做準備或重新讀取。
- `useMusicAnalysisCapabilitySession` 在同一 renderer bridge 上共用 capability state／owner／一份進度訂閱，設定與分析 Workbench 消費同一投影。離頁不 dispose；HMR 才釋放訂閱。歌曲分析與 batch 的 owner、取消及主程序 scheduler 不變。設定重開不重設正在管理元件的進度，過期讀取不覆寫新操作結果。
- `UiModal` 原鍵盤 stack 同時提供模態窗開啟狀態。通知在模態窗期間暫存、隱藏且不開始完成倒數，關窗後恢復；不覆蓋複製、送出或安裝操作，不產生另一套 modal stack。

時間軸匯出保留一份「章節有 N 項需確認」的可展開清單，不改寫時間戳或複製內容。
空場次與讀取失敗也有重新讀取入口；章節使用 readonly textarea，支援鍵盤選取手動複製。
此處複製失敗持續到再次操作／關閉，成功仍使用原短回饋。其他 clipboard caller 保留原預設逾時。
關窗使未完成的讀取／複製結果失效，不能污染重開後的內容。

回饋彈窗的空白說明錯誤屬於 textarea，驗證時聚焦該欄，修改時不搶焦點。
預覽／送出／另存共用單次請求 guard 與草稿 revision；處理中停用輸入，舊草稿的回應不能推進新草稿。
失敗保留預覽與單一另存入口；另存不等於已傳送，持續保留自行傳送說明。取消另存不宣告成功；回報成功保留既有可選取回報碼。

## 整體檢查後的層級與生命週期

設定文件分為曲庫與儲存、音訊輸出、應用程式、外部來源與歌詞、本機音訊處理、公開輸出與 OBS、支援與維護七章，依「章節 → 功能入口 → 子設定／服務列 → 該列的進階欄位」閱讀。
章節由 SettingsSection 統一 canvas 標題帶、raised 內容與分隔線；功能入口、子設定及工具 disclosure 透明共用內容底面，不再依元件種類鋪第三種色帶。
章節內的一般列、功能標題、子設定及進階摘要共用文字軸；圖示與 caret 使用同一前置欄。進階表單沿同一軸對齊，不疊加父容器與 primitive body 內距；窄版隱藏裝飾圖示時仍保留文字軸。
功能入口明確宣告是否有子設定與工具；不能以 slot 函式存在推斷實際內容，避免無子項的歌詞來源出現空白灰帶。
自動分析與 GPU 加速屬於日常偏好；BPM 元件與其他工具／模型管理獨立收合，已就緒時預設收合，執行中、故障或設定導引時展開。
Browser Source 的連接埠與同步 disclosure 屬於該服務，Spout2 是平行服務；OBS 的功能啟用與實際連線是兩個不同狀態。

| 元件                   | 在設定頁的責任                                                     |
| ---------------------- | ------------------------------------------------------------------ |
| SettingsSection        | 功能章節 H2、標題／內容 surface、共同分隔與容器重排                |
| SettingsFeatureGateRow | 功能入口 H3、啟用狀態／說明與明確子項，不偽裝為一般設定列          |
| SettingsDependencyList | 工具／模型管理、就緒／忙碌／待處理摘要，沿用原 domain 操作         |
| SettingsDocumentItem   | 一列資訊、目前值、控制及局部 feedback 的共同對齊                   |
| UiChip                 | 唯讀狀態；不能作為可點擊的啟用控制                                 |
| UiCheckbox／UiSelect   | 已儲存偏好或互斥選項；未知初始值不能假裝確認                       |
| UiButton／UiIconButton | 連線、啟停、下載、清除等明確操作；OBS 連線與 Output 啟停採同類按鈕 |
| UiDisclosure           | 收納所屬功能／服務的進階設定；不代替平行功能分區                   |
| UiField／UiHint        | 欄位驗證及列內讀取／操作故障；重讀按鈕保持自然寬度                 |
| UiNotice               | 區域恢復問題、彈窗操作結果及全域通知；不為每個列內錯誤再套一張卡   |

- 通知 action 的晚到例外不能覆寫較新的同 operation 結果；進度查看 action 也不能覆寫同 id 的後續結果。Modal 或 priority 暫時隱藏已顯示通知時保留剩餘倒數，關閉後繼續，而非重新計滿六秒。
- 曲庫空間按 bridge 共用 domain session，mounted consumer 管訂閱，清理與政策寫入互斥。切頁不重建忙碌狀態或重做操作，舊讀取不能蓋過清理／政策結果。資料夾、播放紀錄與空間初始化並行，避免等待資料夾回應後才在卸載頁面新增訂閱。
- Windows／GPU／自動分析偏好按 bridge 與設定 key 共用原 preference owner，保留進行中的寫入與失敗回饋。設定草稿仍留在各自元件，不進通知 owner。
- OBS 設定 owner 跟隨原連線 owner 共用，保存進行中的儲存／密碼移除與其失敗；回頁不另發相同操作。輸入中的密碼在頁面 scope 結束時清除；送出時只保留是否含密碼的 boolean，成功後仍正確顯示已儲存密碼。
- 診斷 refresh 的 revision 防止清除後補回舊數量；重複匯出與資料夾請求被擋下。讀取失敗顯示尚未確認，不宣告無紀錄；成功清除解除該讀取失敗，匯出成功仍不解除。
- 播放紀錄的讀取／更新故障分開，讀取失敗可本列重試；清除 busy 由原 module owner 保存，舊初始化回應不能恢復已清除紀錄。重讀不重建播放訂閱。
- 工具清單的舊 read 不覆寫較新的操作或 push；更新下載的完成推送優先於較早 request 的晚到失敗。
- 回饋與章節彈窗由 Shell 各掛載一份，跟隨原 module owner，離開設定仍有實際 modal 與鍵盤 stack；關窗依原 revision 使舊回應失效。取消回饋另存保留先前送出失敗及原草稿。

## 操作按鈕的層級與意圖

variant 表達局部操作層級，intent 表達是否會刪除資料或造成已確認的損失；兩者分開判定。

| 操作性質                                   | 入口與確認                                                                                         |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 啟用、連線、啟動、儲存、送出               | 當地主要操作使用 Accent／neutral。                                                                 |
| 停止 OBS、Browser Source 或 Spout2         | 可重新啟動，統一 Secondary／neutral，不以「停止」推斷 danger。                                     |
| 匯出、開啟、重新讀取、重試、還原曲庫資料夾 | Ghost／neutral；還原資料夾只改設定，不刪除原曲。彈窗內唯一主要的複製或完成操作可用 Accent。        |
| 清除播放／錯誤紀錄                         | 刪除已儲存紀錄，選單使用 danger；原確認 owner 保持 Accent／danger 確認與 Secondary／neutral 取消。 |
| 清理去人聲版本、移除已儲存 OBS 密碼        | Ghost／danger 入口，沿用原明確確認；可重新產生版本或重新輸入密碼不代表此次刪除不會失去目前資料。   |
| 移除工具／模型／BPM 元件                   | 選單 danger，沿用原確認；安裝、修復、重新檢查仍為 neutral。                                        |

清空暫存佇列、取消或停止等操作不能只按動詞套用 danger。不可逆清除的停用條件與取消 guard 保持由原 owner 控制；確認視窗不能預設聚焦破壞性按鈕。

## 區塊文案與間距

設定列只保留用途或操作後果；不重述標題、狀態與按鈕。不上傳歌曲、實驗性、清除範圍與故障恢復資訊仍直接可見。
設定頁的功能摘要由 renderer presentation 提供短句，啟用說明的正文與確認版本保持原契約。

| 責任             | 實作與重用                                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 章節間距         | SettingsView 定義 `--settings-section-gap`，一般為 space-6、窄 Folder 為 space-5；選用功能的三章繼承同值。                  |
| 章節外框／內容   | SettingsSection 統一標題 block space-3／inline space-4、內容 inline space-4 與 scroll margin。各章不重複宣告。              |
| 一般列與功能入口 | 共用 `--settings-row-padding-block`：一般 space-4，章節不超過48rem時為 space-3。                                            |
| 子設定           | 共用 `--settings-child-padding-block`：一般 space-3，窄章節為 space-2。工具 disclosure 不加外側 margin。                    |
| 列內關係         | 標題與說明用 space-1；控制群組用 space-2；文字欄／進階群組用 space-3。                                                      |
| 連接埠           | OBS 與 Browser Source 共用 `--settings-port-inline-size`，由五位數的5ch及正式 field padding／border計算，不各自固定6.5rem。 |

區塊與附屬彈窗的非零 padding、margin、gap 和顏色使用正式 token；不得散落像素間距或色碼。
不將不同用途的相同數字硬湊成通用 token。保留有產品用途的幾何值：
閱讀寬度65／70ch、裝置清單的 `min(52vh, 420px)` 捲動上限、診斷搜尋與回饋說明的16rem換行基準，以及明確的響應式斷點。
這些值不作為區塊間距使用；連接埠字元數則由章節內的共用 geometry role集中管理。
