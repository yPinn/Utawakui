# Output 圖層分階段實作計畫

狀態為提案，供排程與驗收使用。階段依[元素工作區 ADR](../adr/0027-output-template-elements-and-property-workspace.md#phases)安排，現行行為以 [Output 外觀契約](../contracts/output-appearance.md)為準。驗收結果另記入[驗收手冊](../operations/output-appearance-acceptance.md)。

## 畫面與操作順序

每個 Output slot 的畫面由下往上是模板背景、主內容、模板前景。模板背景可以是透明底、底色或材質。只為襯托歌詞或卡片文字的背板屬於該內容，與內容一起顯示、隱藏或過場。框線、角標及模板固定標記由模板決定前後關係。Workbench 的棋盤格、深淺底和人物參考圖只供檢視。跨來源的疊放由 OBS 場景管理。

編輯時先選模板與主內容，再調位置、可讀性和背景。背景沿用各模板現有預設，欄位依模板支援能力顯示。有可排序元素時才顯示圖層清單，清單上方對應畫面前方。

只有位置基準和微調的頁籤沿用「定位」。同一對象開放寬高後，使用「版面」並分成位置與尺寸。圖層排序需同時看到多個元素，入口放在調整對象附近。

## 實作階段與退出條件

1. **固定背景與透明基線。** 先用 Karaoke Stack 驗證全幅透明及歌詞生命週期，用 Cover Player 驗證現有透明／柔和／實色選項，再用 Live Stage 抽查標題卡和固定標記。首輪記下各模板的預期塗繪區和空態，執行下表 B01–B08。若出現差異，先定位是預覽輔助、模板自身塗繪或 OBS 合成，再修正相應邊界。既有設定、模板預設與正式來源網址須可沿用。Workbench 和實際 OBS Browser Source 均達到本輪範圍的通過條件才進入下一階段。
2. **用 Cover Player 驗證既有元素編輯流程（P4）。** 沿用曲名、藝人、進度與播放控制的既有元素定義及其可調欄位。在 360×480 和 480×640 核對畫布選取框、側欄選取同步、鍵盤操作、模板允許的可見性、還原及重啟保存。畫布選取框只出現在 Workbench。隱藏元素後能從元素選擇入口恢復。曲名仍依模板規則保持可見，播放控制和音量列維持現有連動。進入配置操作前，先完成該模板的容器相對尺寸驗證。
3. **按模板開放配置與同層排序（P5）。** 有位移需求時，先驗證可移動群組、允許範圍與邊界裁切。至少有兩個在支援尺寸下會重疊、而且互換前後都合理的元素，才讓該模板開放同層排序。背景、主內容、前景之間的順序由模板固定，群組內的遮罩及動態繪製順序也由模板維護。驗收包含兩種疊放順序、鍵盤操作、保存後重開、還原模板順序及切換到不相容模板。Cover Player 可驗證配置，排序試點由符合條件的模板另選。
4. **有跨模板需求時再交付可選共用素材。** 先以兩個確定要共用同一素材的模板驗證各自的裁切、可讀性、fallback 及 OBS 同時顯示成本，再決定是否提供選擇入口。官方 Style Set／Pack 隨 P6 的交付前置條件另行驗收。使用者自帶圖片需要獨立的匯入、保管和刪除流程，前三階段可使用既有內建素材完成。

## 背景與透明驗收

首輪依[既有 Browser Source 流程](../operations/output-appearance-acceptance.md)建立隔離測試場景。OBS 使用 App 複製的正式 URL 和模板原生尺寸，維持 OBS 內建 CSS，關閉額外濾鏡與自訂覆寫。把淺色、深色、複雜圖片設在 Browser Source 下方，每次只切換一種。準備 A 曲（有同步歌詞與封面）和 B 曲（無歌詞、無封面），記錄實際設定與固定播放位置，先暫停比對，再檢查過場。

| 案例                 | Workbench                                                                           | OBS Browser Source                                                       | 通過條件                                                                                                                               |
| -------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| B01 檢視輔助隔離     | 歌詞停在同一行，切換棋盤格、淺底、深底，開關人物參考圖，再重開 Workbench            | 保持正式來源可見，同時操作 Workbench                                     | 檢視輔助只改 Workbench 畫面，未改模板外觀值。正式 URL 無 Workbench／示範參數，OBS 畫面無輔助圖或底色變化。                             |
| B02 透明區與可讀性   | Karaoke Stack 在棋盤格、淺／深底檢查畫布、文字、陰影與邊界                          | 在淺／深／複雜背景以原生尺寸停格比對，再播放看動態邊緣                   | 宣告透明區透出下方來源，文字與必要陰影保留，無整幅黑白底、額外光暈或裁切。複雜底若影響辨讀，單列模板與背景結果。                       |
| B03 模板背景與保存   | Cover Player 依序選透明／柔和／實色，等待保存後重開，最後還原預設。兩個尺寸各跑一輪 | 保持同一正式來源，於保存後比對三模式。兩個尺寸依原生尺寸各驗一次         | 透明區、柔和半透明區和實色區各符合模板預期。實色只填到模板指定範圍，保存與還原後兩端一致。                                             |
| B04 空態、間奏與切歌 | 測未選曲、A 暫停／前後 seek／句間空檔／自然結束、A→B→A                              | 在可辨識的背景上重跑相同序列，錄下換曲前後                               | 句間依模板既有政策留句或清空。清空後襯字背板一起消失。B 無 A 的歌詞或襯字背板，回到 A 時顯示正確內容。模板固定元素依各自空態規則呈現。 |
| B05 前景與過場       | Live Stage 檢查標題卡出入、歌詞與 U／UW 標記                                        | 在深底與複雜背景錄下標題卡入場、退場及第一句                             | 標題卡、歌詞與固定標記依既有時窗與疊放顯示，過場中沒有意外的不透明底，退場後無殘留。                                                   |
| B06 素材缺失         | Cover Player 從有封面的 A 切到無封面的 B，核對封面 fallback 和背景設定              | 在透明／實色各重跑一次，並於 B 重新整理來源                              | B 使用既有缺封面 fallback，無 A 的封面或背景殘影。透明／實色設定保持。解碼故障若另做受控測試，和自然缺圖分列。                         |
| B07 隱藏、重載與重連 | 隱藏期間切歌。重開 Workbench，另測停止／重啟 Output                                 | 逐一測來源隱藏再顯示、切空場景再返回、重載來源和原 port 重連             | 恢復後使用最新曲目、模板及已保存背景。允許短暫載入，恢復後無舊曲、示範或預覽底色。                                                     |
| B08 多來源疊放       | 分別確認歌詞透明與卡片背景為各 slot 的獨立設定                                      | 同時顯示 Lyrics、Now Playing 與下方 OBS 背景，移動及對調兩個來源使其重疊 | OBS 來源順序決定兩者誰在上方，單一 slot 內部疊放維持原樣。透明部分透出下方來源，卡片實色僅在自身塗繪區遮擋。                           |

證據至少保留 App／Windows／OBS 版本、來源類型與寬高、模板及背景設定、曲內時間、靜態截圖和動態短錄影。Workbench 和 OBS 分開標記通過、失敗或未測。可見的 OBS 場景是透明合成的退出條件。離屏 alpha 數值可協助定位。Window Capture 和 Spout 依各自交付方式另驗。

## 素材歸屬與共用條件

魚眼鏡筒的鏡內反光作為模板專用裝飾，沿用星空黑膠的樣式選擇方式。使用者可關閉反光或選擇柔和、標準。模板管理反光的裁切、透明度與播放時序。[反光設定與既有值對應](../contracts/output-appearance.md#歌詞模板呈現)

模板負責素材如何放置、裁切、遮罩和隨內容顯示。素材的檔案歸屬按依賴和版本決定。同一份檔案可以供多個模板引用，各 slot 仍獨立選擇、設定和還原。

| 類型                       | 建議歸屬                                                           | 使用與回復方式                                                                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 專用背景、遮罩、邊框、標記 | 隨模板或同版型家族交付                                             | 例如收據紙面與紙紋遮罩、Live Stage 固定標記。輪廓、對位或動畫依賴特定構圖時，一起更新與驗收。                                                                                                    |
| 通用底色、漸層、可平鋪材質 | 共用底色和漸層的呈現能力。確有多模板需求的檔案才進內建共用素材     | 每個模板宣告可用素材及裁切、透明度、位置和 fallback。素材缺失時回到該模板的內建預設。換模板只沿用新模板也支援的選擇。                                                                            |
| 官方外觀專用背景或裝飾     | 隨 Official Presentation Pack 版本交付，可供 Pack 內的相容模板共用 | 由 Style Set 引用該版本驗證過的 asset id。啟用前驗證完整素材，失敗時沿用前一個良好版本或內建 fallback。                                                                                          |
| 歌曲封面等播放內容         | 沿用曲庫與既有受控媒體路由                                         | 隨目前曲目取得，缺圖走模板 fallback。Cover Player 的封面取色可影響背景，封面仍由曲目提供。                                                                                                       |
| 使用者背景或標誌（後續）   | App 管理的本機素材庫，模板逐一宣告接受的用途                       | Main picker 驗證格式、大小和尺寸後複製，設定只存受管 id。更換某個 slot 的選擇只改該 slot。刪除素材前列出引用，確認後各處回到宣告 fallback。分享 Variant 只帶引用，素材再散布依 Pack 與授權規則。 |
| 棋盤格、深淺底、人物參考圖 | Workbench 檢視資源                                                 | 維持獨立檢視狀態，無正式輸出素材選擇或疊放入口。                                                                                                                                                 |
| 覆蓋整個直播場景的背景     | OBS 場景來源                                                       | 要讓歌詞、歌單和卡片共用同一張全場背景時，在 OBS 放一次，避免各 Browser Source 重複繪製及疊加半透明效果。                                                                                        |

共用檔案以穩定 id 引用。官方 Pack 素材解析到明確版本，並驗證格式、大小、雜湊和授權。正式 Output 透過明列的路由供應已驗證的素材，設定與公開訊息只帶允許的 id。新增或搬動 App 交付的檔案時，一起核對封裝清單與測試。相關邊界沿用 [Overlay Pack 契約](../contracts/overlay-pack.md)。
