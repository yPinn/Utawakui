# 歌詞問題案例回流

此流程沿用既有內容回饋、預覽、送出與另存 JSON，不會切換歌詞來源、保存候選、變更偏移或人工逐字校時。

## 使用者回報

1. 搜尋歌詞時，展開要回報的候選，選「回報歌詞問題」；或在「管理來源」點該來源的回報圖示。
2. 在既有「意見回饋」視窗補上發生位置／時間、實際情況、預期結果及重現步驟。可刪改任何預填資訊。
3. 點「預覽」，確認內容後才送出。無法送出時沿用「另存檔案」，再自行交給開發者；另存不會傳送。

草稿只預填已呈現的歌曲資訊、來源種類、有效的 LRCLIB／NetEase record id，以及已知同步層級。
搜尋列以當下預覽的候選為準，包括尚待確認的更新版本，不等於接受或保存更新。
已保存來源另帶本機偏移數值作為說明；使用中來源取目前畫面值，其他來源取既有來源 metadata。
未知層級明示未確認，不為回報重新讀取歌詞。歌曲名稱與偏移仍是使用者可檢查、刪改的回報文字。

不自動附上歌詞全文、音訊、來源檔名／路徑、URL 欄位、fingerprint 或 timing document。
內容類回報不附診斷事件；App 版本與平台仍走既有環境摘要。開啟草稿不會自動預覽、送出或另存。
取消回報會回到原搜尋／來源視窗，原展開列、來源選擇、待確認更新與校時資料保留。
原本 Settings 的空白回饋入口也保留。

## 開發端整理與重現

收到回報或使用者自行提供的 fallback JSON 後，先人工閱讀；本批不新增自動匯入器、背景蒐集或自動品質標記。
真實回報的歌曲、聯絡方式與說明只保留在 ignored 私有工作資料（例如 `.benchmarks/lyrics-issues/`），不要提交原始檔。

依序完成以下工作，並在私有紀錄以完整 report id 對照：

1. 標記待查證，分類為搜尋／錄音版本、來源格式、來源時間差、內容缺漏、顯示或本機校時；資訊不足先補問，不推定來源有錯。
2. 固定 App commit、來源種類與 record id、曲目版本、使用者指出的時間區段及原始／校時後的觀察。保留原回報，不將使用者偏移或 T2 直接當 provider 真值。
3. 在隔離測試或私有研究副本重現。不要在使用者曲庫執行候選保存、偏好重設、offset reset 或 timing migration。回報可能仍屬無法重現，需如實保留。
4. 找到可重現缺陷後，先建立失敗測試，再修正並保留驗證命令與結果。無法重現或只有主觀偏好時，不宣稱已修復。

## 回到既有驗證

依問題選擇既有路徑，不建立另一份正式歌詞資料：

- HTTP／schema：重用[有界 recorder／replayer](lyrics-provider-contracts.md)與正式 client。
  現有 CLI 是固定歌曲 smoke，不能冒稱它已錄製回報歌曲；指定案例需在隔離的開發 harness 內呼叫同一 recorder API 與正式 client。
  提交前只保留清理後的格式 fixture，重播禁用網路，並確認精確請求匹配與全部回應消耗。
- 錄音分組／來源時間差：用合成 metadata、歌詞文字與時間戳建立最小失敗測試，放在
  `electron/lib/lyricsProviders/` 的對應測試。不要提交回報歌詞或將格式占位文字當文字語意證據。
- 回報／畫面／校時保存：在既有 mounted、composable 或 main handler 測試加入原行為保留斷言，確認來源、offset 與 authored timing 不變。
- 聲學品質：沿用[本機研究與人工聽查](lyrics-alignment-research.md)的 pending／review 流程。
  單一回報不自動變成 reviewed gold，不改正式 gate、固定 40 首 provider corpus、已凍結的研究輸入或評分分母；增加品質案例需另立有版本與人工審核的補充集合。

回覆案例時區分「收到」「已重現」「已有回歸測試」「修正已驗證」。只有實際通過對應測試的修正才標示已驗證。
目前新增的是回報入口與人工整理路徑；沒有代表使用者送出真實回報，也沒有據此宣稱新的歌曲品質通過率。
