# 外觀贊助模式與市場策略比較

研究紀錄：保留 2026-10-20 的模式比較、來源與限制，不在本文件續寫實作計畫。已收斂方向、作品標準與實作順序見[現行計畫](../governance/appearance-sets-plan.md)。

日期：2026-10-20（Asia/Taipei）。狀態：規劃提案，未實作或上架。
方向已確認為功能免費、最小 default 外觀 set 免費、額外自有外觀 set 贊助解鎖；既有 gate、依賴與第三方權利條件仍適用。
本提案接續[功能分層規劃](../archive/community-feature-tiers-plan-2026-10-20.md)，比較付款與未來作品範圍，並依[既有競品研究](competitive-research.md)補查市場策略。

依本輪明確化方向，未來採 by-set 單次取得，各 set 分別提供；不以「當期」或首發合集作為目前方案。現有模板完成度不足，不視為可售作品。
日後的作品身份、交付、驗收與點數取捨見[外觀 set 標準草案](../governance/appearance-sets-plan.md)。
持續贊助先作自願支持，不綁每月新作、不出租既有演出外觀。暫不承諾一次付款包含所有未來作品。
這是依單人社群專案、作品數量與維護負擔作出的建議，不是市場銷量或價格驗證結論。

## 先定義外觀包與使用權

「外觀 set」應是一個有明確名稱、內容清單與版本的設計作品，而非每個小設定都算一包。
完整場景套裝可涵蓋一致風格的 Lyrics、Setlist、Now Playing；單用途作品也可以成為 set，但須標明範圍，不宣稱完整場景套裝。
改色、修正字距、長歌名／多語排版修復、必要可讀性與 reduced motion 不拆成新付費包。

目前 registry 共 8 個模板，分布於 3 個 slot；免費 default 規劃為 queue-board、karaoke-stack、art-card，其餘為 4 個歌詞模板與 cover-player。
這不等於已有 5 套完整且一致風格的外觀 set。現有內容僅作設計與驗收素材；不將這 5 個模板包成首發商品，也不推定每個 set 都要涵蓋三個 slot。未來按作品明列範圍，完成該範圍即可評估為獨立 set。
各模板適用的實際交付版本與外觀素材權利仍需上架前核對；目前 main 的畫面不能直接充當舊公開版本的商品證據。

以下「長期使用／買斷」指取得指定作品版本的使用許可，不是取得著作權、轉售權、所有未來作品或所有未來 Windows／OBS 版本的永久相容承諾。
基本使用範圍建議允許購買者用於自己的營利與非營利直播、錄影及 VOD；不授予原始碼／素材包再散布與轉售，也不包含歌曲、歌詞、封面或字型的額外權利。
字型、GSAP 等仍各依其條款；收費標的是自有設計編排。此處是待定權益範圍，正式條款與退款／交易規則尚未制定。

## 三種模式比較

| 面向             | 單包買斷                              | 一次贊助解鎖全部                                                 | 持續贊助                                                                       |
| ---------------- | ------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 使用者買到什麼   | 指定 A 包的長期使用權                 | 必須選「當期明列合集」或「全部現在＋未來」；兩者不同             | 必須選「有效期間存取」或「期間作品取得後保留」；另有純支持模式                 |
| 未來新增外觀     | 新系列 B 另購；A 的既有範圍修復不另收 | 當期合集不自動含新系列；若明確售全未來，日後標準新作須依承諾納入 | 存取制含會員期內開放的目錄；保留制依公布的期間／作品規則授予；純支持無自動解鎖 |
| 收入特性         | 隨作品與需求發生，收入不固定          | 收款集中；全未來方案可能提前消耗未來作品收入                     | 收入有延續機會，但會流失、失敗扣款與取消，不能等同穩定收入                     |
| 使用者理解       | 喜歡哪包買哪包，容易理解              | 當期合集容易理解；「全部／永久」未寫邊界容易誤會                 | 要解釋扣款、到期、續期、停更月份與取消後的權利                                 |
| 個人維護負擔     | 多包目錄與購買紀錄，客服按作品處理    | 當期合集目錄最少；全未來權限簡單，但創作及長期預期成本較大       | 到期／扣款／補發／取消／會員與非會員目錄，負擔最高                             |
| Local-first 適配 | 適合已取得作品離線使用                | 適合已取得合集離線使用                                           | 長期保留制較合適；存取制需要失效政策，不宜演出中在線撤權                       |
| 社群感受推論     | 像買作者作品；頻繁拆包會有碎片感      | 像支持作者；全未來回饋大但可能低估勞動                           | 像持續支持，也可能被理解為租外觀；取決於權益與取消政策                         |
| 目前建議         | 未來主要作品取得模式                  | 僅保留比較；目前不採當期或無期限全未來                           | 起步只作純支持；外觀會員等有穩定作品節奏再評估                                 |

單包也可以在結帳時讓使用者自願多支持；取得指定包的最低金額與額外自願部分應分清。
有門檻才取得外觀的部分是有對價的權益，不能因稱為贊助就省略商品內容與交易條件。

## 一次解鎖全部的三種邊界

| 變體                       | 未來新增怎麼算                                           | 優點                                             | 代價與適用條件                                                                           |
| -------------------------- | -------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 當期合集／第一輯           | 購買時明列 A、B；日後 C 另計。修復既有 A／B 屬原交付範圍 | 最容易兌現，作品與收入保持關聯                   | 名稱必須是指定合集，不用「全站永久全解鎖」；加入內容不能默默改舊買家的清單               |
| 有期限的新作通行證         | 例如指定起訖期間內發布的標準作品納入，已取得作品期滿保留 | 比全未來可控，能回饋早期支持者                   | 額外管理期間與作品歸屬；期限不是保證期間一定有新品，宣傳須清楚。這是混合變體，非目前首選 |
| 所有現在＋所有未來標準作品 | 標準新系列一律納入；委託／聯名若要排除，必須原先明示     | 權限敘事簡單，適合少量作品且主要靠自願支持的作者 | 是對未來作品的實質承諾；不能收款後以換系列名稱排除，也不能假定未來人人還會再贊助         |

若作者願意讓所有未來外觀都成為支持者回饋，第三種並非不可選；它代表選擇「支持作者」而非持續賣作品的收入模式。
目前尚無完成作品、產能、付費意願與持續支持資料，沒有根據承諾全未來能長期負擔成本；這三種合集變體僅保留比較，目前方向改為未來各 set 單次取得。
將來只對新加入者調整方案，原有清楚承諾仍需履行；不以社群專案名義任意收回已承諾範圍。

## 持續贊助的三種邊界

| 變體           | 會員取消／到期後                                                          | 新增作品                                                     | 適用評估                                                                     |
| -------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 外觀目錄存取制 | 到期後不能再選未擁有的會員外觀，回 default 或已買外觀；演出中不突然撤畫面 | 有效期間可用會員目錄中的新作；不自動取得長期使用權           | 不利本案低維護與離線定位，目前不推薦；不把競品可下載資產的行為當本案到期政策 |
| 期間作品保留制 | 會員期間依規則取得的作品保留，往後新作不再送                              | 建議只送有效期間新發布的標準 set；加入前作品另購或明列入會包 | 可以討論，但需確切的授予日期、補發與跨月規則；不能承諾每月固定新品而沒有產能 |
| 純持續支持     | 不影響已購作品或任何功能                                                  | 沒有自動新作權利，可提供不保證頻率的創作紀錄；具名致謝需自願 | 最符合當前社群定位；收入為自願支持，不能包裝成有固定外觀回饋                 |

若會員一個月能領整個歷史目錄並永久保留，實質上就是「當期合集的另一個價格」，並非可靠的長期訂閱設計。
若選期間保留制，缺新品月份就不會新增作品權利；使用者必須一開始知道支持的內容，而非付款後才發現沒有每月作品。
會員權利可以未來另行設計，但現階段不需要先建立會到期的外觀使用權。

## 未來新增與修復的共同規則

| 變更類型                                                      | 建議如何算                                       | 不應如何算                                    |
| ------------------------------------------------------------- | ------------------------------------------------ | --------------------------------------------- |
| 字體 fallback、長歌名、多語排版、同步顯示 bug、必要可讀性修復 | 在明定支援範圍內維護原包，免費核心同步修復       | 為修好原本買到的功能強迫再買新包              |
| 同一 set 已列明的變體／完成原先承諾的內容                     | 原擁有者包含                                     | 把未完成交付改稱新作收費                      |
| 完全不同的藝術方向或新增獨立 set                              | 單包／當期合集另計；全未來／期間方案依原承諾     | 每個色號與微小調整都拆包                      |
| 原本只賣歌詞模板，後來獨立新增同風格歌單／播放中套件          | 若原先清楚只售歌詞，可列擴充包；購買頁直接標範圍 | 原宣稱完整套裝，之後補齊卻再次收費            |
| 聯名／客製委託                                                | 可另售，前提是有適用資產權利，且原方案已明列例外 | 收款後才補上未來聯名全部排除                  |
| App 大版本升級／換機／重裝                                    | 外觀權利不因重裝消失；技術相容與支援期間另行明定 | 用每次 App 更新或持續線上驗證製造再次付款需求 |

規劃中的共通底線：已取得作品可離線使用，能恢復購買紀錄；外觀服務故障不影響免費功能；不保證永久下載伺服器或永遠相容未知平台。
停止維護時應有明確通知、已交付版本保存與權利延續安排；實際交付、驗證與復原方法留待後續設計。

假設起初已有 A、B，第二期發布 C，第三期發布 D：單買 A 者不自動得 B／C／D；當期 A＋B 合集不含 C／D；全未來方案含 C／D；只在第二期有效的期間新作保留會員取得 C 並保留，第三期 D 另計。
這個例子中的作品與期間是假設，用於檢查規則，不代表已存在的商品或發布時程。

## 對 Utawakui 的行銷定位建議

主要受眾先聚焦 Windows＋OBS 的歌回／翻唱創作者，尤其已有自己的音訊、願意整理歌詞，又在意畫面風格的人。
只需純文字歌單的人有更輕量替代；需要深度 VST／ASIO／錄音路由的人也有不同工具。現階段不以補齊所有競品能力作為行銷目標。

推薦訊息是：「功能免費，把自己的歌曲整理成一場歌回；用喜歡的外觀支持後續創作。」
免費下載與觀看實際演出示範為主要入口，外觀 gallery 與支持為次要入口。
對外清楚標「免費工具＋可選外觀包／支持方案」，比單獨標 donationware 更能解釋付費取得什麼；純自願支持另外標示不附解鎖承諾。

| 主張                       | 展示方式                                                                        | 現況／限制                                                                               |
| -------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 功能免費、基本畫面完整可用 | 同一首自備音訊從曲庫到播放、歌詞與 default OBS 輸出                             | 核心免費是此輪方向，尚未有付費版本；使用發布版本的真實錄影，不以 main 預覽取代已交付證據 |
| 外觀是可選的設計作品       | 同一段歌詞、相同大小與背景，並排比較 default 與額外模板；先展示成品，再展示設定 | 不刻意醜化免費版；必要字級、位置、配色、讀音與同步能力不作付費差異                       |
| 為歌唱畫面而做             | CJK 長句、短句、間奏、逐行與真實 T2、不同背景的示範                             | T2 必須有可信資料；不能把行內估算宣傳成模型已完成精準逐字                                |
| 同一播放狀態帶動畫面       | 展示實際換曲、暫停、歌單／歌詞／播放中投影一致                                  | 不宣稱比競品更穩定或更低延遲，除非有同條件測量                                           |
| 支持自有設計並尊重社群成果 | 在作品頁寫清設計內容、依賴致謝、免費能力與費用用途                              | 不把模型權重、字型或外部歌詞服務包裝為專有素材，不聲稱付費附帶歌曲利用許可               |

目前可主打的是各模板本身的排版與動態風格；「整場完整風格一致」則是更有價值的未來 set 標準，需要補足同風格的跨 slot 作品後才能宣傳成已提供。
這是從市場比較得出的設計與展示方向，不是已證實的獨家優勢。

## 推廣順序與驗證

1. 先讓少量真實歌回使用者以免費 default 完成一次排練／OBS 測試，記錄卡住的步驟；外觀收入不能補救難以開始使用的流程。
2. 依[既有網站內容規劃](public-site-content-v0.4.0.md)的操作端／觀眾端前後對照，製作一段完整示範與短版外觀比較；示範素材須有適用使用權，並標實際版本。
3. 先用標準驗證樣本了解偏好的款式與實際使用問題；作品尚未達標，不安排首發合集或收款。完成後再測個別 set 的取得意願。
4. 社群貼文以 X 的短動態展示、YouTube 操作教學為優先候選；BOOTH 可作日語素材受眾的商品發現候選。這是渠道建議，不代表已選付款平台或已符合其賣家條件，不建立帳號、發布、寄信或聯絡他人。
5. 先繁中，依實際詢問再增加日／英說明；不因競品多語就承諾目前沒有的完整介面語言。
6. 作品與使用案例增加後，才測單包／當期合集的選擇；持續支持若已有自然需求，再討論作品保留會員，而非先承諾固定月更。

可請願意參與的使用者提供同意公開的實際畫面、使用心得與問題；試用者先核對表述，公開素材不暴露真實曲庫、私人 OBS 設定或未授權內容。
不強制直播角落放 logo、追蹤／轉發才取得基本功能，也不在演出中彈出贊助催促。非營利支持與有對價外觀取得的說明分開。

| 待驗證問題           | 可用指標／方法                                                 | 判讀用途                                           |
| -------------------- | -------------------------------------------------------------- | -------------------------------------------------- |
| 免費入口是否真的可用 | 同意參與的試用者中，完成本機匯入＋default OBS 輸出的比例與卡點 | 先修導入；不把下載量當使用成功                     |
| 有無外觀需求         | 看過同條件比較的人中，明確選擇作品／願意取得的比例與理由       | 檢查設計價值，區分只喜歡示意圖與實際想用           |
| 單包或合集偏好       | 相同內容與明示權益下的選擇訪談；上架後才有真實交易資料         | 小樣本只提供線索，不能當市場轉換率預測             |
| 收入是否值得維護     | 實際收入扣手續／退款等直接成本，再對照設計工時與客服量         | 尚無資料，不預測獲利；免費使用者的合理問題仍要處理 |
| 是否適合持續支持     | 自願續期情形、取消原因、穩定出品能力與支持者預期               | 有持續支持不代表大家想租外觀                       |

初期用自願訪談與手動彙整即可，不為行銷自行加入 App 遙測。若日後使用網站分析，另說明蒐集範圍與同意方式；不假設既有 App 提供 funnel 數據。
本輪沒有使用者調查、付費意願實驗或銷售資料，所以不提出市場規模、預估轉換率、建議正式售價或營收承諾。

## 建議採用的起步方案與待決事項

目前方向為「免費功能＋default set＋未來各 set 單次取得＋獨立自願支持」。
先制定與驗證作品標準；未來新 set 分別取得，既有作品範圍內的修復不另收。合集只保留為往後可評估的銷售組合。
持續贊助先不影響任何外觀使用權；暫不售所有未來作品的永久通行證，也不建立到期撤銷外觀的模式。

目前先固定 set 的範圍、完成標準與支援／相容性要求；作品達標後，才決定價格、交易平台、既有使用者保留政策及權利復原方式。
金額依作品內容與實際意願測試決定，不直接換算國外通用 overlay 價格。平台手續費、稅務與交易條款在平台選定時另查，本輪不推定任何登記或稅務豁免。
外觀收款仍可能影響同一 App 的第三方 API 使用分類；不因只賣外觀就視為所有上游已核准，沿用既有未決條件且目前不洽詢商用方案。

本輪僅保存比較與推薦；未更改程式、gate、entitlement、付款／帳號、公開網站或競品歷史紀錄。

## Discord 裝飾取得與點數參考

建議以「挑選一個 set → 預覽 → 單次取得 → 加入已擁有清單 → 可反覆套用」作為未來體驗。
新 set 是新作品，另行取得；已取得 set 的權利不依訂閱續期，也不因 App 改版或商品下架自動消失。
買斷指指定作品使用權，不代表著作權移轉、所有未來作品、永久下載服務或未知平台的永久相容承諾。

Discord 的 [Shop FAQ](https://support.discord.com/hc/en-us/articles/17162747936663-Shop-FAQ)區分直接購買、組合與 Nitro 權益，說明已購裝飾可保留使用；[Orbs FAQ](https://support.discord.com/hc/en-us/articles/30593690165783-Discord-Orbs-FAQ)則另行定義任務獎勵點數，Orbs 不能購買、轉讓或換現。[Quests FAQ](https://support.discord.com/hc/en-us/articles/22225719947543-Discord-Quests-FAQ)包含遊玩、直播與觀看影片等任務。
本案借鏡「裝飾按件取得、收藏與預覽」，不推定必須複製任務、廣告或點數；Discord 的特定會員裝飾與任務獎勵也不能一概當成永久買斷。

## 是否需要點數或贊助廣告

不需要。外觀的擁有權與取得途徑應分開：未來即使增加直接購買、活動贈送或合作回饋，都只授予同一個 set 的使用權，不需要先有通用錢包。
「贊助廣告」若指觀看合作廣告換獎勵，是另一個營運模式；若指贊助專案後給兌換額度，也應另外定義，而非混成同一種點數。

| 方式                       | 使用者得到什麼                                   | 新增負擔                                                                   | 目前建議                                                                 |
| -------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 按 set 直接取得            | 清楚列價的指定作品使用權                         | 訂單／權利紀錄、復原與退款處理                                             | 作為未來標準途徑；價格與支付方式留待作品就緒                             |
| 自願贊助，不附點數         | 支持開發，不自動獲得特定外觀                     | 支持說明與收款紀錄                                                         | 可與購買並存，清楚分開標示                                               |
| 贊助後取得兌換額度         | 按門檻換 set；若有固定金額／額度關係，實質有對價 | 金額與額度對應、餘額、折抵、退款／撤回與重複領取                           | 暫不採用；如果只送一個指定 set，直接記錄該 set 權利比錢包簡單            |
| 充值購買點數               | 先付費取得餘額，再兌換外觀                       | 帳務、餘額保存、換機復原、價格換算與剩餘額度處理                           | 目前不需要；不可為了看起來像商城就引入中介貨幣                           |
| 看廣告／完成贊助任務換點數 | 不直接付款，以參與合作活動取得獎勵               | 廣告或合作來源、合約與可用地區、完成驗證、防重複領取、資料同意、結算與客服 | 暫緩；目前沒有已確認的廣告來源、適用服務或收入，不能先假設能支付設計成本 |

點數不是讓使用者免費取得外觀的唯一方法；default set、作者自行發布的免費 set 或明確的活動贈送都能達成。
未來若有廣告，應由使用者主動選擇，與歌曲、歌詞、OBS 畫面及演出操作分離；不在播放或輸出中插播，也不為獎勵擅自收集曲庫或演出資料。
