# 字幕風格 Proposal 格式

公版字幕的目標是讓使用者直接套用預設，就能在 OBS 呈現近似 AE 製作的構圖、圖層與換句效果。提案應說明這些設計如何在歌詞長度、語言及背景變化時成立。

複製本格式建立候選並登錄。來源與已確認決策須能追溯，產品採用狀態以 spec 為準。尚待比較的設計可以列出多個版本，方向選定後再把精確參數與實作方式寫入 Build Spec。參見[候選索引](README.md)與[模板建立格式](build-spec-template.md)。

## 身份與來源

- 名稱、working ID、提案日期、整理日期。
- 使用者原始意圖、chat 標題／ID／turn ID／時間與時區，或其他正式來源。
- 參考圖片／影片連結及時間段。指出最想保留的瞬間，說明辨識度來自字形、構圖、材質或換句方式。
- 參考檔是否實際保存、可否讀取、是否已查核來源；外部參考與可散布產品素材分開記錄。
- 指向 spec 的採用狀態，以及本文件中已確認／初步建議／待決事項的區分。

## 體驗與差異

用一句話說明畫面想產生的體驗，再列出演出情境、閱讀優先順序與相對既有模板的差異。列出刻意保留的藝術規則及本提案不處理的需求；不要僅以參考作品名稱代替設計語法。

## 定格構圖與圖層關係

- 附一張代表性定格或構圖草圖。標出畫布比例、字幕錨點、主體安全區、透明區及遮罩邊界。比較不同版位時，使用同一組歌詞與背景。
- 當前／前後句、曲目資訊、裝飾與讀音各自是否出現。
- 由底到頂列出文字、描邊、陰影、遮罩和裝飾等實際圖層。說明遮罩裁切或遮住哪一層、哪些圖層一起動、效果可外擴到哪裡，以及換句時新舊句的前後關係。
- 標出效果的作用範圍，區分 Overlay 自身圖層與 OBS 底層來源。用代表性的深淺或複雜背景確認文字與主體仍然清楚。

### 歌詞與舞台群組

依下表分開記錄兩組的外觀與附帶動效。公版預設的定格與分鏡要看得出兩組如何配合。未採用的項目可標為無，尚待選擇的項目標為待定。

| 群組 | 外觀示例                           | 附帶動效示例                                   |
| ---- | ---------------------------------- | ---------------------------------------------- |
| 歌詞 | 正文、讀音、描邊、承載文字的色塊   | 逐字掃色、換句進退場、跟著文字移動的遮罩或光暈 |
| 舞台 | 背景材質、暗場、固定光區、舞台裝飾 | 掃光、薄霧、色光變化、間奏燈光                 |

- **效果歸屬與堆疊**。對每項效果分別標記它服務的群組、作用對象和實際堆疊位置。掃過文字前方的舞台光束仍歸舞台組。承載文字、隨字幕移動的底帶歸歌詞組。依定格圖列出背景、內容與前景的遮擋關係，並標出模板須維持的順序。參見[圖層與堆疊提案](../../../adr/0027-output-template-elements-and-property-workspace.md#stacking)。
- **獨立開關**。列出可單獨開關的效果候選、預設狀態及關閉後的畫面。關閉舞台掃光時，歌詞仍能按原時間換句。若提案讓舞台在間奏繼續演出，另寫出沒有歌詞時舞台組如何呈現。
- **成組保留**。列出必須一起移動、顯示或切換的元素，說明拆開會失去的遮罩、可讀性或交接關係。若底帶、文字與遮罩共用同一段進場，就在分鏡裡標記這組依賴，並寫明關閉可選效果時保留的基本畫面。

## 長句與混語案例

- 用一組自製歌詞比較一般短句與壓力案例。至少納入一個長句及一個混語句，可由同一句涵蓋。記錄語言組合、預期行列數、閱讀順序與可接受的斷點。
- 寫清楚超出容量時的處理順序，例如先換行，再縮字或分頁。標出優先保留的構圖特徵、字詞或讀音，以及哪一種變化會讓設計失去辨識度。
- 用相同畫布比例比較案例。未知的容量、字級下限或分頁條件標為待定，保留完整歌詞及來源時間。

## 歌詞資料與同步

- 最低時間需求；分列 T0、T1、原生 T2、T1+ 估計資料的預期行為與缺資料回退。
- 是行級切換、片語切換、逐字進度還是純裝飾；估計不得宣稱精確逐字。
- 來源範圍、聲部、讀音、共用文字處理及模板 policy 的需求；未知能力先列問題。
- 不改 canonical 原文、ID 與時間；分句或分頁需維持來源對映。

## 鏡位與演出編排

- 描述預設鏡位與取景。可以是固定構圖、Overlay 內的虛擬鏡頭，或個別圖層的透視與位移。若取景需要 OBS 實際攝影機或場景來源配合，列出由誰控制及需要什麼配置。
- 寫清楚哪些時段維持鏡位，哪些事件會換鏡。把切換接到換句分鏡，標記換鏡前後的閱讀焦點與主體安全區。全程固定鏡位的提案也要說明換句時視線如何交接。
- 列出哪些圖層跟著鏡頭移動，哪些只在局部做動畫，哪些固定在畫面上。包含字幕、背景、遮罩及有採用的光效，並標記換鏡時字幕何時可讀。
- 兩套編排若有不同的觀看焦點、鏡位順序或交接節奏，且各自套用預設就能形成完整演出，可列為獨立預設候選。同一套編排中的強弱或幅度差異，先評估可調欄位。

## 換句分鏡與播放狀態

用三到四格分鏡表達進場、穩定、換句交接與退場。每格寫下可見的句子、移動或遮罩變化，以及相對歌詞時間的觸發點。標出當前句何時可讀、新舊句是否重疊，以及哪些動態跟隨歌曲、哪些是獨立裝飾。草圖與文字分鏡皆可，時長及強度可先以相對節奏描述。

補充短句來不及完成動畫時的處理，以及暫停、seek、快速換曲時應呈現的畫面。列出空資料、間奏、重連、隱藏恢復、停用與 reduced motion 的預期結果。

## 公版預設與可調邊界

以開箱預設的代表性定格與分鏡作為基準。先列出由模板維持的構圖比例、堆疊、語意色與換句節奏，再列出使用者可調的候選屬性。說明每項調整影響哪些圖層、是否會重排文字，以及調到邊界時必須維持的可讀性與設計特徵。

| 候選屬性 | 作用對象／目的   | 選項或值域 | 初始值 | 既有能力／需新增／待評估 |
| -------- | ---------------- | ---------- | ------ | ------------------------ |
| 待填     | 模板、群組或元素 | 待定       | 待定   | 待評估                   |

選項、值域與初始值可先記為待定。優先對照共用屬性目錄，並記下後續需要比較的預設與極端組合。

## 可行性、素材與待決事項

- 技術候選、與現行 owner 的關係、需先驗證的缺口及可能依賴；不先選無證據的新引擎。
- 字型／圖片／圖形來源、fallback 與散布查核工作；歷史連結或先前授權說明不等於本輪已完成查核。
- 按影響列出需要使用者補充、構圖比較或原型才能回答的問題。
- 哪些初步方向被新描述取代，以及保留的來源；以目前收斂內容取代平行草案。

## 驗收構想與下一步

列出能證明體驗的案例：多語短／長句、資料缺失、切換／seek、字型失敗、明暗／複雜背景、alpha、reduced motion、生命週期與效能。此處描述計畫，不填虛構結果；精確支援矩陣與預算在 [Build Spec](build-spec-template.md) 固定。最後只列下一階段需解的決策，不自動展開實作。
