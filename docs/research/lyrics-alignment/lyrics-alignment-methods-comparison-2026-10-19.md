# 歌詞對齊可實現方法、環境分級與採用顧慮

本文保留當輪研究與分母；目前跨批次選型及未決項集中在[研究結論](lyrics-alignment-summary.md)。

日期：2026-10-19。本文整理現有產品、已實跑研究與目前有可用工具的主要方法族，供漸進式環境選型；不是宣稱已測完所有模型或證明某條路線普遍最佳。本輪 Qwen 品質實驗見[活動與內容一致性評估](lyrics-qwen-quality-2026-10-19.md)，同分母模型對照見[Qwen／Whisper.cpp 配對實測](lyrics-alignment-candidates-2026-10-19.md)。正式 gate 與預設下載均未變。

## 先區分希望改善的行為

| 任務                      | 可用證據                               | 驗收重點                                                  |
| ------------------------- | -------------------------------------- | --------------------------------------------------------- |
| 已有 T1，改善行內詞塊起點 | 原文、粗行時間、人聲與音素／字元訊號   | 同一原文切點、起點誤差、缺界回退、T2 優先                 |
| 從無時間全文找到句子      | 內容辨識、長序列匹配、重複 occurrence  | 錯句／漏句／副歌順序、整曲定位；不能由 oracle T1 成績推論 |
| 產生完整逐字 T2           | 字首、字尾、拖音、休止、連唱           | 起訖都準、文字完整、不能用下一字開始當本字結束            |
| 確認正在唱這份歌詞        | 不接受已知歌詞提示的 ASR／音素內容證據 | 錯歌、錯版本、缺字、唱詞變體與正確歌曲誤拒率              |
| 人聲活動與休止            | VAD、歌唱分類、分離 stem、能量         | 唱歌召回、伴奏假活動、長音／氣聲／和聲                    |
| 重複句與 verse／chorus    | 文字 occurrence、音訊自相似、段落模型  | 重複文字有自己的時間；相同歌詞不必然是副歌                |
| 不同聲部顯示              | diarization／重疊活動、使用者聲部標籤  | 換人、同唱、伴唱分離；音高不直接代表性別                  |

這些任務可共享音訊分析，但不能用其中一項的成功代替另一項。活動存在不等於內容正確，時間合法不等於真的唱了那句，顯示詞塊也不等於已得到人工 T2。

## 文字、DSP 與節奏方法

| 方法                                 | 實現／證據狀態                 | 可提供的效果                                          | 成本與顧慮                                                                          | 建議                                      |
| ------------------------------------ | ------------------------------ | ----------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------- |
| 現有 T1 字長分配                     | 產品現況；本輪同分母 A 基線    | 無音訊分析即可逐塊顯示、穩定回退                      | 拖音、停頓、快唱不按字長均分；沒有聲學精度保證                                      | Basic 保留；本功能新增模型為零            |
| 匯入或人工編輯 T2                    | 產品現況                       | 經校對後可準確指定起點與字尾                          | 人工成本、來源粒度／校對品質不一；需保留 provenance                                 | 永遠優先於模型估計；模型只供可撤回草稿    |
| 人聲 onset＋頻譜／能量＋單調動態規劃 | 已有研究實作                   | 不需新權重，找聲學候選，再用 T1／文字長度約束整條路徑 | 前輪中文有收益，日文／韓文與長尾未穩定改善；伴奏也有強峰                            | 可作低成本研究或提示，不當通用可靠性 gate |
| BPM／beat／downbeat 弱約束           | 已有 Beat This! 及研究消融     | 提供節奏位置、離群提示、候選排序                      | 前輪確認組非零拍格線權重退步；拍點不等於音節                                        | 使用者可檢視；本功能不要求先安裝節拍環境  |
| 鼓 stem onset／細分格線              | 可實作，尚未完成同條件獨立實測 | 提供打擊樂瞬態與節奏密度，輔助候選                    | 目前 quick／general 的伴奏＋guide 不等於獨立鼓 stem；需額外分離、時間、模型與新驗收 | 保留小型控制實驗；不直接硬吸附            |
| F0／note onset／旋律約束             | 工具與研究方法可實作           | 長音、換音、句末拖音及部分候選邊界                    | 一字多音、多字同音、滑音；需音素／文字共同解碼                                      | 若後續研究字尾或拖音，再評估 joint model  |

前輪 DSP、拍點數字以「句內字首」為主，與本輪「固定詞塊切點」不是同分母，不能混成模型排行榜。具體設定與失敗案例見[T1 切分實測](lyrics-t1-acoustic-segmentation-2026-10-19.md)。[Beat This!](https://github.com/CPJKU/beat_this)提供 beat／downbeat；這項能力本身不辨識歌詞。歌唱音高與對齊聯合建模已有[研究依據](https://arxiv.org/abs/2202.01646)，但沒有證據支持把每次音高改變視為換字。

硬吸附尤其需要避免：120 BPM 一拍 500 ms，最近整拍可移動 250 ms；細分拍、swing、搶拍、拖拍與自由速度又有不同誤差。應由文字／音素與人聲時間證據決定候選，節拍只提供弱先驗。

## 給定文字的模型對齊

| 方法                             | 目前證據                                                     | 優點                                                            | 採用顧慮與環境                                                                                             |
| -------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| HubertFA 歌唱音素                | 已完成相同中日 T1 詞塊對照；歷史確認組 ≤100 ms 約 77.5–81.4% | 歌唱用途；重用 Node ORT、kuromoji／wanakana；不需 Torch         | 確切 release 權重／字典使用與分發證據未補齊；本 checkpoint 不支援韓文；錯內容仍可強制對齊。維持 blocked    |
| Qwen3 FA 官方 wrapper            | 本輪固定中日 22 案例＋壓力案；同分母約 46.3–70.6%            | 直接對已知文字；原曲與 guide 都能起跑；權重／程式授權證據較明確 | 完整新增環境約 2.903 GB；錯歌與長尾仍需獨立檢查；多語支援清單不是歌唱精度承諾                              |
| Qwen3 FA HF native／既有單位路徑 | 前輪另做完整起訖及四語 runtime／installer-layout probe       | 可直接使用已有單位，減少自行日韓斷詞依賴；有共用環境方向        | 與本輪 wrapper、revision、切點任務不同；不能拿較小布局或不同分母成績直接宣稱替代更佳；仍缺產品交易生命週期 |
| 中文 CTC trellis／Viterbi        | 前輪已實跑中文完整起訖                                       | 音素／字元 posterior 可提供對齊與缺字證據；權重小於本輪 Qwen    | 這份模型主要中文；OOV／繁簡／異體字與歌唱域差異；字尾未達採用要求；不同語言微調需不同權重                  |
| 中文＋日文 XLSR CTC              | 有明確模型候選，未完成本輪配對實測                           | 可實作每語言 CTC 對齊，後續可研究音素 posterior 可信度          | 兩份權重合計約 2.548 GB，另加完整 runtime／依賴；沒有 Windows 完整容量或同曲品質結論                       |
| MFA／Kaldi 音素對齊              | 可用中日 acoustic model／字典，未測目標歌曲                  | 傳統給定文字方法、字典可控；模型 archive 較小                   | 需 Kaldi／MFA／tokenizer 完整環境；朗讀域未必適合唱歌；字典與 acoustic model 要分別遵守條款；OOV 要處理    |
| SOFA／其他歌唱專用 aligner       | 有開源實作，尚未選定本產品 checkpoint／字典                  | 歌唱設計，可研究音素與持續音                                    | 每份實際權重、語言與字典須逐一查授權和 provenance；code license 不足以解除權重 gate                        |

確切版本、容量口徑與授權證據見[權重 gate 查核](lyrics-acoustic-weight-license-gate-2026-10-19.md)。例如 MMS_FA 的非商用權重不能因程式庫授權寬鬆就列入一般商業工作流選配。MFA 的 acoustic model 與 pronunciation dictionary 是不同輸入，[官方對齊流程](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/alignment.html)也要求它們；僅下載兩個小模型不能當完整環境。

給定文字的強制對齊通常會努力為錯歌詞找路徑。模型本身的 logits／score 需要以正確與錯誤內容標註校準，不能直接當「這份歌詞正確」的機率。限制到 T1 或短句可以減少跨句搜尋，也會把錯外框鎖死；前輪固定短句切法未穩定勝過窗口方法，不直接拿 oracle 外框當產品真實準確率。

## ASR、內容檢查與混合方法

| 方法                                                | 已做到什麼                                        | 額外成本                                                                | 主要風險／判定                                                                                    |
| --------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Whisper.cpp base／small 原始 token 時間             | 已完成同曲 Windows native 實推論；不需推論 Python | 完整新增 0.169／0.508 GB，另計共用 FFmpeg                               | 本輪詞塊時間未勝均分，small 未穩定勝 base；不作此功能主要對齊器                                   |
| Whisper ASR 內容核對                                | 本輪已有不帶歌詞提示的實際轉錄，重用作內容證據    | 若產品尚未安裝，仍需完整 native 模型；重用研究 raw 不代表未來零推論成本 | ASR 會漏詞／幻覺；唯一配對不足要區分歧義與不相容；繁簡、kana／kanji、同音與演唱變體不可隨意改原文 |
| stable-ts／whisper-timestamped／attention alignment | 有可用實作，需另鎖定完整 adapter 與環境           | 選定 Whisper 權重、框架與附帶依賴；本機未實量                           | 與目前 CLI token 起點不是同一方法；可接受已知文字的 alignment API 須逐一確認；歌曲需重新實測      |
| WhisperX／ASR＋語言 CTC＋VAD                        | 有成熟工作流程可研究                              | ASR、每語言 aligner、VAD；若加 diarization 另加模型                     | 各模型授權／語言能力各自查核；不能把 Whisper 的 MIT 當整條流程授權或把英文示例外推中日歌唱        |
| Qwen＋VAD 硬篩選                                    | 本輪已實測                                        | JIT 額外約 2.305 MB，重用本輪 Torch                                     | 唱歌漏判會大幅誤拒；時間較乾淨可能只是刪掉大量正確切點，不宜直接採用                              |
| Qwen＋ASR 支持才保留                                | 本輪兩個 ASR 大小與時間支持均已消融               | Qwen 加一個 ASR／VAD 的完整閉包                                         | 有助減少錯歌與部分長尾，但正確切點損失也大；不能只看保留者精度                                    |
| Qwen＋未知保留、明確矛盾回退                        | 本輪後續探索，重播同一實際模型證據                | 單一或雙 ASR；串列載入可降低同時 RAM 需求                               | 未知不代表可信；雙 ASR 共享家族／訓練偏差，不能當完全獨立驗證；需新盲測與誤拒預算                 |
| 原曲／guide 或多模型共識                            | 前輪已做原曲／guide 對照；可繼續擴展              | 通常多一次推論；若尚無 guide，還有分離成本                              | 共識可提高保留者精度，但覆蓋可能大降；兩者一起錯仍會一致，不自動平均出新時間或補字                |

[stable-ts](https://github.com/jianfch/stable-ts)有 alignment 與 refinement 工作流程，[WhisperX](https://github.com/m-bain/whisperX)則把 ASR、對齊與可選 diarization 組合起來。它們是值得控制實驗的路線，但本次沒有下載或驗收這些完整環境，不能列為已通過的手動選配。

內容核對要在未提供預期歌詞的條件下取得音訊證據。把歌詞當 ASR prompt，再以辨識結果跟原歌詞相同來驗證，會造成循環支持。若加入繁簡轉換或日文讀音比較，必須只改比較鍵、保留原文範圍，並另外驗證同音誤接受；本輪沒有為了提高結果事後改寫文字。

## 活動、段落與聲部：可一起分析，但不直接拆字

| 輔助方法                               | 實現狀態                                      | 有價值的用途                        | 不足與條件                                                                                                                   |
| -------------------------------------- | --------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| RMS／數值靜音                          | 已有                                          | 拒絕全靜音、驗 PCM 完整性           | 伴奏也有能量，不能證明人聲或內容存在                                                                                         |
| Silero speech VAD                      | 本輪固定 JIT 真實推論                         | 活動／呼吸空檔提示、品質診斷        | 一般 speech 與 singing 域不同；本輪不新增 torchaudio／Silero package，只用既有 Torch 載本機 JIT；ONNX 可行但未跑同等移植驗收 |
| YAMNet Singing 等事件                  | 前輪已做 ONNX 對照                            | 部分歌曲的粗人聲／事件提示          | 約 16.11 MB 只是模型＋map；唱歌召回不穩、約半秒 hop 不具逐字解析度；不作硬 gate                                              |
| 專用 singing VAD／pitch-aware detector | 有研究與工具可實作                            | 有望減少長音／氣聲漏判              | 仍需選定權重、歌唱標註、授權及跨語測試；不能只換一般 VAD 門檻假裝已解決                                                      |
| 文字重複 occurrence                    | 已有 identity 與回歸檢查                      | 副歌重複時仍保留各次順序與時間      | 字串相同不證明音訊段落相同，不能去重或重用同一時間                                                                           |
| Chroma／自相似／audio DTW              | 可實作                                        | 提示重複段落、粗順序、版本差異      | 和聲／編曲重複不等於唱詞相同；cover／移調／刪段要另外處理                                                                    |
| All-In-One／SongFormer 類結構模型      | 前輪有受限研究；正式仍受各自 gate 限制        | intro／verse／chorus 候選與曲式摘要 | 模型紀錄不是人工真值，段落邊界誤差大於詞界；部分 checkpoint 條款受限，不自動下載或硬裁逐字音訊                               |
| Speaker diarization／重疊偵測          | 可研究，未接入本功能                          | 對唱／合唱角色標記、換人提示        | 歌唱與和聲很難；需區分同時多聲部，不以高低音直接標男女；人工修正與不確定標籤不可少                                           |
| Audio fingerprint／檔案 hash           | 檔案 hash 已有；可信參考 fingerprint 可另研究 | 抓來源變更、已知錄音版本不匹配      | 必須有可信參考；hash 只能證明同一檔，不證明歌詞本來就對；cover 也可能合法不同錄音                                            |

Silero 官方定位與介面是 [speech VAD](https://github.com/snakers4/silero-vad/tree/v6.2.3)，不是歌唱逐字辨識器。專用音樂工具也要查權重條款，例如 [madmom LICENSE](https://github.com/CPJKU/madmom/blob/main/LICENSE)把 code 與模型／data 的條款分開，不能只看到 code license 就假定所有內附模型可一般分發。

更上層的歌唱聯合模型，例如 [STARS](https://aclanthology.org/2025.findings-acl.781/)，提供音素、音符與演唱技巧的研究方向；需要更完整標註與環境，不屬這輪小型可靠性修正。雲端 forced alignment 也可另作使用者主動同意的對照，但會增加上傳、網路、計費與資料處理條件，本輪沒有串接服務或上傳歌曲。

## 目前可規劃的環境級距

下表 GB 均為十進位，當前已實量的新增邏輯落盤，包含既存 Python caches，排除既有 app／OS、歌曲、副本與 UV／job cache；以本輪固定官方 wrapper 為 Qwen 配方。其他歷史路線或未量測環境不混入這張表。

| 配置                      | 不重算共用 FFmpeg | 含本輪 FFmpeg | 角色與條件                                     |
| ------------------------- | ----------------- | ------------- | ---------------------------------------------- |
| Basic                     | 0 GB              | 沿用現有能力  | T1、匯入／人工 T2、文字／時間結構檢查          |
| Whisper base 單獨         | 0.169 GB          | 0.391 GB      | 可做小型 ASR 研究；本輪不採為詞界對齊器        |
| Whisper small 單獨        | 0.508 GB          | 0.731 GB      | 較大 ASR；不能由容量直接推論更好的詞界         |
| Qwen 單獨                 | 2.903 GB          | 3.125 GB      | 已知文字對齊研究，錯歌／長尾仍是限制           |
| Qwen＋Silero              | 2.905 GB          | 3.127 GB      | 活動提示；硬 gate 未過品質驗證                 |
| Qwen＋base＋Silero        | 3.074 GB          | 3.296 GB      | 單一 ASR 的內容核對研究                        |
| Qwen＋small＋Silero       | 3.413 GB          | 3.636 GB      | 較大內容核對；需證明增加容量值得               |
| Qwen＋base＋small＋Silero | 3.561 GB          | 3.784 GB      | 雙轉錄矛盾／時間共識研究，Whisper DLL 只計一次 |

組合數字按實量閉包去重加總；並非做過產品 prepare／repair 的完整安裝驗收。單一 ASR 組合是按決策依賴推算的聯集；本輪消融 harness 會同時校驗兩份轉錄，尚未交付可單獨啟用的 recipe。本輪 VAD 資產含 JIT、LICENSE 與固定介面來源共 2,304,580 bytes；未增加新的 Python distribution。舊 UV cache 仍另約 1.012 GB。下載、安裝暫存、修復時新舊並存峰值及 NTFS 配置量尚未完整量測，空間檢查不能只採完成後 payload。

其他重要路線：HubertFA 先前獨立安裝約 0.491 GB、已有對應 Audio Python 時增量約 0.466 GB；仍因權重證據 gate 無法正式提供。HF-native Qwen 先前共用布局約 2.502 GB、保留舊環境並存約 3.032 GB；中文 CTC 約 1.931／2.461 GB，這些是先前不同配方與產品遷移假設下的研究數字。MFA 約 0.206–0.210 GB 僅是中日模型／字典 archives，完整 runtime 未量測；不能把它們與本輪完整 payload 直接比較。

目前 64 GB RAM 主機已跑 CPU 配方。Qwen 主工作集約 6.10 GB、單案 private／commit 約 7.21 GB；新增 VAD worker 約 0.23 GB。若串列分階段載入，不能簡單把所有峰值相加；若同時執行則必須重新量測整棵程序樹。8 GB 不直接承諾這份 Qwen float32 配方；16 GB 只列下一階段與 Electron／OBS 共同負載的測試目標；32／64 GB 也不是可以無限制並行的理由。GPU／量化沒有本輪同曲證據，不宣稱增加 VRAM 就提高精度。

## 採用順序與顧慮

先維持 Basic 與可回退的詞塊預覽，再用本輪證據選研究路線。正式手動選配需要同時滿足：正確與錯誤內容的品質／誤拒預算、新中日人工或盲測資料、完整 artifacts／notices、固定 runtime／probe、串列 scheduler／lease、取消及 repair／remove、安裝空間與低 RAM 驗收，以及使用者可見的不確定狀態。支援多語、權重可下載或某組 median 較低，都不能單獨滿足這些條件。

比較時優先看相同分母的成功切點與正確切點保留，再看錯內容接受、長尾、coverage、完整環境及載入成本。活動與 ASR 的輸出應允許「支持／矛盾／未知」，其中未知仍需保留研究標記或人工確認；不能把它自動提升成可信。

本文件是研究比較，沒有新增正式模型選項、放寬 HubertFA 或其他 gate、改預設下載、重寫 canonical T2 或提交 commit。
