# 歌詞音訊對齊：研究結論

整理日期：2026-10-21。本頁集中跨批次研究的選型與未決項；產品可用狀態以[規格](../../spec.md#3-目前功能現況)為準，實作邊界以[聲學估計契約](../../contracts/lyrics-acoustic-estimate-contract.md)為準。

## 目前結論

Basic 維持既有 T1 顯示與 T2 優先，不增加必備模型。研究優先使用原 HubertFA 對齊、Whisper small 獨立檢查內容，繁簡只用於比對，漏詞先警示。已提供本機研究試用；App 正式模型準備、歌曲詞塊產生與預設下載仍未開放。

實驗入口另已提供手動準備環境、伴奏後自動產生及歌詞頁手動套用／停用；正式 catalog 不變。後續完成[純英文驗證與進度](lyrics-english-validation-2026-10-20.md)及[混語長句顯示第一階段](lyrics-mixed-phrases-2026-10-21.md)：英文仍有正常誤拒與漏詞漏檢，混語只在既有可靠起點切換，未新增混語模型推論。下列中日歷史分母不與這兩輪合併；人工時間及混語語意仍 pending。

零下載配對實驗顯示，base 在固定16案保留相同主要構造攔截與正常輸出，但漏詞警示1／3少於small的2／3；完整推論支援檔集合約1.328／1.668GB，不能只比較權重。兩首可確認的既有guide供HubertFA有時間改善跡象，ASR仍用原混音較穩；guide同送ASR本批增加回退／漏擋，暫不採用。人工標記仍pending，詳見[配對與完整成本](lyrics-model-pairing-2026-10-19.md)。

人工品質與特定權重／字典的使用範圍仍待確認，兩者分開驗收。研究輸出不寫入 canonical T2，也不因時間合法或模型一致就自動套用。

LyricFloat 的 Demucs＋faster-whisper base／stable-ts 另列環境成本候選：固定資產 metadata 去重合計約 0.514 GB，安裝後／RAM／同條件品質尚未測，不取代目前選型。先比較不新增分離與重用現有 guide 的消融，再決定是否安裝完整配方；詳見[效果與完整環境重評](lyricfloat-cost-2026-10-19.md)。

## 核心問題與取捨

| 核心問題               | 可做方法與目前選擇                                  | 限制／未決項                                                       |
| ---------------------- | --------------------------------------------------- | ------------------------------------------------------------------ |
| 整句拆詞、改善行內顯示 | 原文分詞＋HubertFA 聲學起點，獨立估計可撤回         | 分詞本身不會提高時間精度；缺界合併或退回T1，正式T2優先             |
| 用BPM／鼓點吸附字詞    | 拍點作弱提示；onset／能量保留控制實驗               | 拍點不等於音節；目前沒有足夠證據採硬吸附，獨立鼓stem尚未同條件驗收 |
| 錯歌、錯句、缺唱誤接受 | small不帶預期歌詞轉錄，再檢查強內容矛盾             | 已攔下本批構造目標；舊壓力組仍有漏擋，未知證據不等於內容正確       |
| 正常句被誤拒           | 比較鍵做繁簡統一；保留原文與時間                    | 本批正常輸出24→25，未經人工確認；鄰近救援／外語過濾沒有額外收益    |
| 歌詞漏字               | 有唯一前後文字錨點的內部插入警示                    | 本批抓到2／3可分析目標；ASR本身漏辨或重複歧義仍未知，不硬拒整句    |
| 日文缺界與長尾         | 優先比較HubertFA；Qwen原始span、粒度與行框另查      | 補切能增加輸出但未保證更準；不能用均分覆寫後稱為聲學改善           |
| 重複句、段落、不同聲部 | 保留occurrence身分；段落與speaker／重疊活動另行研究 | 尚未交付可靠的整曲段落或聲部標記；音高不能直接當性別               |

其他候選與完整取捨見[方法比較](lyrics-alignment-methods-comparison-2026-10-19.md)。尚未做同條件測試的模型不排名；不將NC或未知授權直接解讀成效果較差。

## 同條件證據

最新配對組是中日各兩首、每首正常／片語錯配／漏詞／整句靜音，共16案。正常片段共要求140個內部切點，只有兩首日文35點有外部provider參考；中文不能報時間準確率，provider也不是人工真值。

| 正常日文、固定35點 | T1均分 | Qwen | 原HubertFA | HubertFA＋small繁簡內容檢查 |
| ------------------ | ------ | ---- | ---------- | --------------------------- |
| 誤差≤100ms         | 15     | 12   | 22         | 22                          |
| 誤差>500ms         | 2      | 5    | 1          | 1                           |
| 缺界               | 0      | 6    | 5          | 5                           |

HubertFA單獨仍接受3／3片語錯配與3／3整句靜音目標；加內容檢查後兩者均0／3輸出。每種構造另有1個英文不支援目標，保留在原4案分母，不算成功攔截。漏詞警示2／3、正常新增警示0；這些是構造案例的代理結果，不能報成人工誤接受／誤拒率。

原HubertFA與Qwen使用不同frontend／採樣率／decoder約束，數字比較整套可用配方。舊確認組的百分比與新35點不混算；內容檢查只篩選，沒有改正起點。原53列人工標記仍pending，聽查入口選其中15優先＋4漏詞對照，不是假隨機盲測。

## 環境、權重與開放條件

本機研究流程不需要Qwen、Torch或GPU。9個固定資產下載合計778,532,833 bytes（約0.779GB）；這不含既有Node依賴、FFmpeg、解壓／安裝峰值或研究音訊，不能當完整環境容量。下載完成與資產驗證也不等於模型已載入；可執行步驟見[研究試用手冊](../../operations/lyrics-alignment-research.md)。

原HubertFA repo的Apache-2.0與small的既有授權證據分開記錄；特定HubertFA release權重及附帶字典的適用範圍仍未充分確認。這是證據未決，不是已證明禁止或侵權；原HubertFA也不能直接套用另一份GTSinger checkpoint的NC條款。開源、非商用或官方直下載不會自行補足未知範圍，詳見[權重查核](lyrics-hubertfa-fresh-2026-10-19.md#開源專案的非商用手動選配)。

早期試用已有4案實跑及取消／失敗清理證據，保留一次未重現、根因未知的worker失敗。後續英文與混語兩輪已完成隔離 profile 的可見 Electron／Browser Source 功能及回退驗證，詳見上述日期報告；這不等於人工時間通過，也不抹除早期失敗。正常誤拒／漏擋／長尾、人工聽查與權重範圍仍影響正式手動選配決策；目前 gate 和預設下載不變。
