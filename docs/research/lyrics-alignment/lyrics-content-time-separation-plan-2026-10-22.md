# 歌詞內容與時間證據分離：最小研究方案

日期：2026-10-22。僅規劃，尚未實作、重播新判定或執行模型。沿用既有 CPU 模型／環境與固定快取，不下載、不改 offset、不 commit；產品 gate 與現有回退不變。承接[前段重判](lyrics-offset-zh-front-cache-check-2026-10-22.md)及[固定六句計畫](lyrics-offset-zh-six-line-plan-2026-10-22.md)。

## 問題與最小邊界

目前 `checkContent` 先依 ASR token 起點是否落在來源句框前後 500 ms 篩文字，再計算內容支持；`assessCompleteness` 的漏詞查核也使用此時間篩選。後續 O1 唯讀診斷確認：同一份轉錄其實有前三字，因 token 時間在左界外而未計入；另有一字替換。文字層為 13／14，既有篩選為 10／14，UTF-8、NFKC 與繁簡沒有造成差距。這些是既有診斷，不是本方案的新測試結果。

目標是讓「內容不足」與「ASR 詞時間不一致」各自說明原因，避免用 ASR 詞時間決定已辨出的文字是否存在。只新增研究報告的獨立證據欄位；不把 O1 改判通過，不恢復中後段補測，也不新增產品套用行為。

## 分開保存，保守合併

| 證據     | 提議判定依據                                                       | 不足時處理                                      |
| -------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| 文字內容 | 固定盲 ASR 片段的完整文字，沿既有正規化、覆蓋與矛盾規則比對        | insufficient／contradiction，不能靠聲學時間救援 |
| 出現位置 | 來源 occurrence、ASR segment／文字範圍、原窗口、鄰句順序與唯一對應 | ambiguous／unverified；文字高相似也不可校時     |
| 聲學時間 | HubertFA 原始 index 0 首詞、原窗口與配方、裁框及既有研究限制       | missing／unsafe；文字支持不補造時間             |

另保留舊 `evidenceState`、漏詞警示與 ASR token 時計診斷。ASR 詞時間有偏差時，只影響其時間可信度欄位，不刪除合法轉錄文字；非法 raw、超預算、來源／時鐘身分不明仍阻擋整份證據，不能藉文字欄掩蓋。

原則是所有必要證據同時成立：內容支持、出現位置唯一、缺詞防護符合原研究要求、聲學時間可用，才可能進入原六句 offset 一致性檢查。任何一項未知或不符，就保留原值與 T1 回退。人工時間仍 pending，不由這些欄位代填；有研究候選也不代表人工驗收通過。

## 固定文字範圍與防護

1. 先固定同一錄音／來源／offset／raw SHA／模型配方與原有最多 30 秒窗口，保留原文及 UTF-16 範圍。不擴音訊窗、不換轉錄、不搜尋整曲其他位置補字、不使用預期歌詞 prompt。
2. 第一版只研究「一個完整 ASR segment 對一個完整來源句」。比較整段文字，保留額外字與替換，不用最佳子字串裁掉不合內容。以窗口內原來源句與 ASR segment 的順序建立單調、一對一對應；在原支持門檻下若有多種可行對應，就記 ambiguous，不選最高分那條。相鄰句可核對時一併檢查順序；缺少必要定位脈絡就 unverified。原曲首尾沒有鄰句時只記已知來源邊界，不捏造錨點。
3. 同時檢查整份來源的重複正文，以及固定窗口內的重複 ASR 片段／匹配路徑。來源文字唯一只是必要線索，不能單憑此宣稱音訊 occurrence 唯一。ASR 合併多句、拆成多段、跨句或有無法分配的鄰句內容，第一版保留未知；不按字數拆、不內插或靠 token 時間強分配。不完整的窗口邊緣片段也不能當完整句支持。
4. ASR segment 的時間只核對與原窗口的合法身分；不用其首字距 T1 起點多近來決定文字支持。ASR token 時間仍完整保存作差異診斷，但不作本方案的聲學起音，也不與 HubertFA 起點平均。
5. 數值門檻原樣保留：中文至少 4 個有效字元且覆蓋 ≥0.8 才能支持；至少 4 字且覆蓋 ≤0.2 的明確矛盾繼續阻擋。既有額外文字警示的至少 3 字／比例 ≥0.35，以及插入查核的雙側各 2 字唯一錨點、2–8 字範圍均保留。繁簡／NFKC 只供比較，不新增同音替換、模糊修詞或外語刪除。
6. 原時間篩選結果不被覆寫：明確 contradiction、近數位靜音拒絕及既有漏詞警示不得被新的文字相似度救回。新舊結果不取最高分、不採任一支持即可通過。原為 insufficient 時，新文字結果最多提供一份獨立內容支持；還須通過上述定位、防護與聲學條件。

漏詞查核須使用同一個已唯一分配的完整 ASR segment，不能先把多出的字裁掉。沿用插入警示與歧義規則，沒有觸發警示不等於「沒有漏詞」；遇到無法唯一比較、替換遮住錨點或證據不足，保留 unknown，不填 clear。若原 offset 研究要求排除缺詞疑慮，此處 unknown 仍停止，不能因文字覆蓋高就放行。

現行插入查核在未觸發時通常也只回傳 unknown，本方案不新增「已排除漏詞」的證明。第一階段因此可能只改善原因分類，仍無法產生 offset 候選；是否容許這類 unknown 進入自動候選，需要另行決策與驗證，不包含在本輪。

這是改變證據的使用方式，須視為新研究配方；數值不變並不能自行證明誤接受風險不變，必須先驗證負例。舊分母、失敗與停止結果保留，不重寫歷史數字。

## O1 的預期呈現與未決項

O1 可呈現「文字相似度已有支持線索」「ASR token 時間與來源句框不一致」「出現位置／聲學可用性／缺詞疑慮仍分別待核」。13／14 只來自既有文字診斷，尚未按本方案完成片段分配與防護，不能宣布新 contentState 已通過。

其末字替換不會被繁簡或同音規則消除。新方案若只能改善說明而仍無法滿足校時條件，結論仍是不能校時。保留 HubertFA 的原始時間與裁框保護，不移動 offset 讓 ASR 時間看起來相符。

## 最小驗證方式：先離線，不補模型

後續另獲授權後，僅以固定 O1／O2、既有錯段／刪詞／重複句快取及少量標記為合成的資料副本驗證；原始證據不修改。沒有對應 raw 或人工標記就列缺測，不重新推論。以下只列驗證要求，本輪未執行：

| 固定組別                         | 必須檢查的行為                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| O1／O2 原快取                    | 同列舊判定與三類新證據；O1 內容可獨立說明，不能自動通過校時；O2 原有文字支持不得無故退步，新增定位不足須另列原因 |
| 合法 ASR 詞時間偏移副本          | raw 文字／segment／窗口身分不變且時計仍合法時，文字與序列對應不因 token 跨 T1 篩選界限改變；只變時間診斷         |
| 既有錯段／錯序／錯版本控制       | 原已明確攔下的案例不得被完整片段相似度救回；來源順序矛盾保持拒絕或未知                                           |
| 既有刪詞與額外文字               | 原已觸發的警示不得消失，不靠移除鄰句字或挑子字串通過；原漏檢仍列在分母，不能宣稱已補足                           |
| 重複句與多匹配路徑               | 即使文字高度相同，occurrence 歧義仍阻擋校時，不借另一副歌的轉錄或時間                                            |
| 合併／拆分／邊緣片段副本         | 第一版保持未知，不均分、不插值，也不將缺定位轉成支持                                                             |
| 來源／raw／配方 stale 或非法時計 | 舊證據不可沿用；不以文字支持遮掉身分錯誤，不補造時間                                                             |
| 聲學缺首詞／貼框與人工 pending   | 內容支持也不產生有效起音或整曲候選；原六句與人工驗收規則不變                                                     |

固定 raw 清單與角色須在未看新方法結果前凍結，所有目標都列入比較。若已攔負例變成可用、警示消失、重複句被錯配，立即停止，不調門檻追求 O1 通過。這些控制只能檢查已知失敗模式，不能替代自然錯版本的大樣本或人工時間驗收。

## 調整位置與成本

第一步只在獨立研究報告增加新欄位與配方版本；暫不改 `engine.js`、產品 sidecar／schema、modal 或 renderer。若日後實作，從 `content.cjs`／`completeness.cjs` 抽出純文字比較與插入查核所需的共用邏輯，另設有界片段對應；原時間查核作為獨立診斷保留，不能以偽造 start／end、將 boundary 全設 false 或拉寬原句框來呼叫舊函式。

規劃中的離線驗證只處理既有文字／JSON；新增模型工作、下載與環境容量均為 0。新文字對應方法的耗時與誤接受效果尚未測，不給加速或通過率承諾。完成固定負例驗證以前，不恢復《雪 Distance》中後段補測、不改正式 gate，也不接產品。本輪僅保存方案與入口。
