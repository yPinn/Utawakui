## 取捨結論

研究基準維持 HubertFA＋small 的原混音內容檢查。既有 base 是可繼續驗證的低容量替代分支：本批主要構造錯詞／靜音攔截與正常保留相同，但漏詞警示較少，不能宣稱等效。

既有 guide 只送入 HubertFA、內容檢查仍聽原混音，是值得保留的下一個人工聽查候選。
把 guide 同時送給 ASR 沒有形成整體優勢，本批甚至出現正常回退與漏擋；不採用為預設前處理。
這些是小型、構造案例的代理結果，並非人工確認準確率，也不是產品已開放的新模型選項。

LyricFloat 的 stable-ts／faster-whisper 配方本輪不安裝、不實跑。現有 GGML base／small 不能直接充當 CTranslate2 模型；同為 Whisper 或同為 `.bin` 不代表格式相容。
依據見 [whisper.cpp 模型說明](https://github.com/ggml-org/whisper.cpp/blob/v1.9.2/models/README.md)、[faster-whisper 模型轉換](https://github.com/SYSTRAN/faster-whisper#model-conversion)與 [stable-ts adapter](https://github.com/jianfch/stable-ts/blob/main/stable_whisper/whisper_word_level/faster_whisper.py)。本輪測的是獨立轉錄後的內容檢查，沒有宣稱重現其強制對齊。

原凍結研究音訊是 mono16k，本輪 guide 也先使用相同格式；沿既有 worker，HubertFA 再解碼至 44.1 kHz、Whisper 至 16 kHz。這不是原生 44.1k 音訊品質對照。
訊號檢查補強本批對應證據，不是替舊 manifest 補造完整 provenance；缺項不以其他歌曲或不同錄音替換。

## 耗時、RAM 與保護驗證

八案 guide 分階段新跑，模型載入計入既有 worker／CLI 執行；ASR 每個窗口各載入模型，非長駐服務吞吐量：

| 階段          | Wall seconds | 觀測程序族工作集最大加總 bytes | 約 GB |
| ------------- | -----------: | -----------------------------: | ----: |
| HubertFA 八案 |         78.6 |                  1,934,974,976 | 1.935 |
| base 八案     |         45.7 |                  1,090,101,248 | 1.090 |
| small 八案    |         94.7 |                  1,682,685,952 | 1.683 |

請勿把三個峰值相加。198 份樣本依當下 parent PID 鏈核對 owned coordinator，排除已重用 PID 或離場 race 的 39 rows；觀測包含 Node、decoder／ASR 與 conhost，不含觀測用 PowerShell 或其他桌面工作。
要求的取樣間隔為 700 ms，實際包含 CIM 查詢耗時；工作集可能重複計入共享頁，這是取樣最大值，不是真實並行峰值、最低實體 RAM 或低 RAM 電腦驗收。階段邊界依 elapsed wall time 切分，有小幅啟動偏差。
原混音 base 16 案的模型作業時間合計約 81.7 秒；small 歷史合計約 186.4 秒是不同執行時段，不據此宣稱嚴格速度倍率。舊 worker 的 `peakRssBytes: 0` 是缺觀測，沒有當成零 RAM。

46 份原音訊、歌詞／來源 manifest、校時、人工 labels、selection、references 與正式 gate 檔案前後 SHA 全同，且原音訊／歌詞 SHA 仍對上原 selection。人工 reviewed 數仍為 0。新推論只寫 ignored 研究目錄，沒有呼叫 App 保存、切來源、offset reset 或 timing migration。
研究統計 helper 有 malformed denominator、未知內容、PID 重用、資產重複與退化訊號測試；來源相符檢查不用歌詞時間或參考答案。獨立審查與檢查結果記錄於本輪工作紀錄，不將測試通過當成真人聽查完成。
