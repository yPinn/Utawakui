# Qwen3.5 4B：任務分離與候選斷點對照

本輪支持先修正任務介面與候選呈現，再判斷模型能力。把每個候選切點的完整左右原文呈現給模型，效果比原本局部預覽好；單純減少候選沒有進一步改善。這是固定合成案例的離線診斷，尚無產品採用或自動刪除歌詞的依據。

## 範圍與對照

沿用[前輪實測](lyrics-text-qwen-pilot-2026-10-23.md)的自製語料、opaque occurrence ID、Qwen3.5 4B Q4_K_M 與 pinned CPU runtime。新一輪經使用者授權，獨立凍結 protocol、程式快照與成本時鐘，沒有修改或重算舊輪資料。

繁中、簡中、英、日、韓各選三個長句：有標點 l1、無標點 l2、句內混語對唱 l4；15 案各比較四組，共 60 次。各語系另選括號製作署名 c3、對唱 s2、和聲 s3、引用製作詞的實唱 s4；20 案各比較兩組，共 40 次。總共 35 個不同案例、100 次請求，無重試、調參或補跑成功案例。

| 組別 | 任務與 prompt                                    | 候選呈現                                        | 輸出                          |
| ---- | ------------------------------------------------ | ----------------------------------------------- | ----------------------------- |
| A    | 前輪原始分類＋拆句                               | 全部詞界、左右各約 16 grapheme 的局部預覽       | 原五欄 schema                 |
| B    | 僅拆句；增加選子集的正例、完整子句與角色保護指示 | 與 A 相同的候選及局部預覽                       | lineId、breakIds              |
| C    | 與 B 完全相同                                    | 同候選、同 ID，每個位置顯示完整左前綴與右後綴   | 與 B 相同                     |
| D    | 與 B 完全相同                                    | 完整預覽，按固定規則減到最多八個候選，保留原 ID | 與 B 相同，允許 ID 隨子集收窄 |
| E    | 僅辨識文字用途                                   | 原文、語言與 opaque ID，沒有斷點建議            | lineId、kind                  |

A→B 同時改任務、prompt 和輸出 schema，不能單獨歸因某句指令或只移除分類。B→C 只改候選預覽；C→D 只改候選子集。D 不讀答案：排除剛好落在角色標籤後的位置，優先標點與角色開頭，其他切點要求兩側各至少六個字母／數字 grapheme，再以固定幾何間距補足八個。

候選先於推論凍結並量測覆蓋：A／B／C 各 212 個，包含全部 25 個參考斷點，15 案完整參考都可達成；D 共 120 個，只含 24／25 個參考斷點，14／15 案可達成。D 遺漏 ko-l2 的 offset 16，該案仍留在 15 案主分母。參考只用於評分與覆蓋檢查，不送入模型、不參與候選篩選。

## 拆句結果

完整符合表示所有選中位置與作者預設分組一致，不等於一般語意準確率。拒收一律保留整句，仍列入分母；參考邊界精確率只統計接受後選中位置，拒收的原始回覆另完整保留。

| ---------- | ------------ | -------- | ------------------ | ------------------ | -------------------- |
| A 原配置   | 0／15        | 5／15    | 1／25              | 1／25              | 4／15                |
| B 獨立拆句 | 0／15        | 1／15    | 9／18              | 9／25              | 0／15                |
| C 完整預覽 | 6／15        | 0／15    | 15／16             | 15／25             | 0／15                |
| D 粗候選   | 4／15        | 0／15    | 13／16             | 13／25             | 0／15                |

B 已減少逐詞過切及角色落單，但完整符合仍為零。C 在同 prompt、同 schema、同候選下達到 6／15，邊界精確率 93.75%、召回 60%；這是本輪最直接支持「候選呈現影響選擇」的對照。C 的六個完整符合包含全部五案混語對唱，以及英文無標點長句。多數其餘案例只切一刀，較作者預設少一個子句。

D 雖較快，完整符合降到 4／15，候選缺失也限制上限。在仍可達成參考的 14 案中為 4／14，僅作次要條件統計，不能取代主分母。減少候選同時可能移除正確位置並改變模型選擇，不能宣稱較少候選更可靠。

失敗與替代分組均保留，`｜` 僅在下列說明標示位置，沒有寫回原文：

- 繁中 l1：A 為「當｜最後｜一班｜車｜駛｜過｜河岸，…」；B／C／D 都改為「當最後一班車駛過河岸，｜我把沒說完的話留給晚風，等你回頭再一起走。」後者可視為合理兩組，但與原三組參考不同，不能直接說語意錯誤。
- 簡中 l2：B 為「当街灯一盏一盏｜熄灭我｜仍把…」；C 為「当街灯一盏一盏熄灭｜我仍把…」，修正了明顯不完整片段，但仍未選全部參考位置。
- 繁中 l4：A 因角色落單拒收；B 切在第二聲部的「Stay with me」之後；C／D 改在 `[男]` 前切開，標籤、唱詞與「（oh oh）🌙」均完整保留。結構驗證通過本身不代表對唱語意分組正確。
- 日文 l1：C 仍輸出「最後の電車が川を渡る｜とき、言えなかった言葉を風に預けて、君が振り向くのを待っている。」完整預覽並未解決所有語法依附。
- 韓文 l2：B／C 選「거리의 불빛이 하나둘 꺼져도 ｜네 이름을…」；D 刪掉此位置後輸出「거리의 불빛이 ｜하나둘 꺼져도 네…」。D 仍保留另一參考位置 offset 31，模型卻未選，不能把全部退步只歸因候選缺失。
- A 的五個混語對唱均因角色落單拒收；B 的 en-l4 仍同樣拒收。原始 breakIds 與拒收原因保留，未以 fallback 掩蓋失敗。

## CPU 與記憶體成本

實機 Ryzen 7 7700、約 63.16 GiB RAM；CPU 推論／prefill 各四執行緒、一模型一 slot、無 GPU、無 thinking。量化資產與 runtime 的版本、完整 SHA 與大小沿用前輪，另在開跑前以串流雜湊驗證。模型 2,740,937,888 bytes；CPU runtime b11669，commit `620d2225cc436ab0b001e3200e590e3b286ef9ab`。本輪零下載，沒有安裝 Python 或其他執行環境。

wall 是完整生成請求，不含逐請求 token preflight；第一個 A 包含 process-cold 首次推論，所有組共用一個 process，按案例輪替組別次序。每組每案僅一次，p95 採 nearest-rank，小樣本不能估人口尾端或宣稱統計顯著。CPU 秒為前後最近採樣括住請求的 server CPU 差值，可能含少量邊界開銷，不等於 wall 秒。

全部 100 次從模型啟動計 871.873 秒，約 14.531 分鐘，啟動就緒 2.681 秒。server 累積 3379.906 CPU 秒，PowerShell sampler 121.609 CPU 秒，runner 累積約 9.796 CPU 秒；後兩者為量測開銷，沒有混進模型 CPU 秒。原始各語系成本與 TTFT 見 JSON。

單一共享 server 的 peak working set 4,683,739,136 bytes（約 4.362 GiB）、採樣 private bytes 峰值 2,388,283,392（約 2.224 GiB）；每次取 server private／working set 較大者，加 runner RSS 和 sampler private／working set 較大者，保守採樣合計峰值 4,847,312,896 bytes（約 4.514 GiB）。共 6753 筆樣本，最大間距 221ms。這是全輪共享峰值，不能推論各 arm 的獨立實體記憶體差異，也不是逐瞬間無漏失的硬體峰值。

原成本上限保持：4096 context 含 512 output 預留、每請求 30 秒、全輪 45 分鐘、保守 process 記憶體 8 GiB、下載 4.6 GB／安裝 5.5 GB 及磁碟預留 10 GiB。資產重用，已留存權重與展開 runtime 約 4.072 GB，含下載 ZIP 約 4.091 GB；本輪開跑前空間約 39.773 GiB。沒有為失敗重設時鐘。

## 保真、驗證與資料

推論介面只收原文、語言、opaque ID、允許的候選與固定指令，不提供時間、案例分類答案或參考分組。模型只能選候選 ID，主程式按來源 slice 重建；角色落單、不合法 ID、重複／逆序或 schema 不符回退原句。E 沒有斷點或刪除欄位。全輪原始回覆、SSE、拒收原因、請求、process telemetry 和凍結程式快照均留存，沒有刪除失敗。

- [完整數據](lyrics-text-qwen-ablation-2026-10-23.json)：100 筆原始決策、parts、候選與輸入 payload、覆蓋、成本、語系分母與 receipt hash。
- [方法與執行入口](../../scripts/research/lyricsTextPreprocessing/ablation-study.md)：五組介面、停止限制與匯出方式。研究程式沒有產品呼叫入口。
- ignored `tasks/lyrics-text-qwen-ablation-20261023/`：protocol、全部原始 request／SSE／result、samples、clock、lifecycle、測試與最終 verification 收據；模型資產留在前輪 ignored 目錄。

逐筆核對 100／100 份輸出 parts 拼回原文，hidden 均為 false；89 份接受、11 份角色落單拒收，皆保留原始回覆。實際 prompt＋output 最多 1162 tokens、output 最多 65、wall 最多 15.345 秒，cache 與 reasoning 均為零；原語料、前輪程式／報告與本輪六份凍結來源／快照 SHA 一致。server 與 sampler 的指定 PID 均已核對不存在，Git HEAD／index 未動。基線其他工作異動另列於 verification 收據，未覆寫。

Focused runtime 測試四檔 33 項通過；純 contract／scorer／candidate design／lifecycle 四模組 coverage 為 lines 98.32%、branches 93.20%。這不代表 transport、CLI 或完整產品覆蓋率。程式 lint、語法、文件格式與 Markdown 檢查通過。沒有執行產品 build、Electron／OBS 或人工母語品質驗收，本輪僅研究腳本與文件。

## 後續判斷

失敗不能直接解讀為 4B 不理解語意：拆句介面確實影響輸出，尤其完整左右預覽；但 C 仍有欠切與日文依附失敗，尚不足以讓模型主導產品分頁。若續做研究，應保留獨立分類／拆句和完整預覽，先固定新盲測案例、母語多個可接受分組，再比較受語法／角色約束的候選；幾何式縮減不能當通用解法。

本輪至此停止，沒有再調 prompt、下載模型、接產品、修改原文或時間。實唱、角色、對唱與和聲的原文始終保留，任何分類候選都不能自行成為刪除指令。
