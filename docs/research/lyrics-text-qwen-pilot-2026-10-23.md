# Qwen3.5 歌詞文字預處理 CPU 實測

日期：2026-10-23。接續[可行性與已核准限制](lyrics-text-preprocessing-feasibility-2026-10-23.md)。本輪實跑 Qwen3.5 2B／4B Q4_K_M，各 60 個固定自製案例，另做 8 次獨立診斷。完整[數據與原始回覆](lyrics-text-qwen-pilot-2026-10-23.json)、[凍結語料](lyrics-text-preprocessing-corpus-2026-10-23.json)與[研究 runner](../../scripts/research/lyricsTextPreprocessing/README.md)可追溯。沒有接產品、讀取私有歌曲、改原文、賦予／修改時間或 commit。

## 結論

本配置不宜直接採用。4B 在製作資訊分類上明顯優於 2B，但兩者都沒有建立穩定改善語意分組的證據；合法 JSON 與原文保真不等於分組正確。先維持規則基線及使用者確認，不增加模型預設下載或自動隱藏。

2B 將 15 個非同字歧義的實唱／對唱／和聲案例全部誤標為製作資訊；4B 在這 15 案沒有此類誤標，但其中 4 案回答 ambiguous，不能算成 15 案都正確確定為歌詞。兩者均把 5 個與 credits 完全同文字的實唱案標成候選，沒有棄權。這些同字歧義不能靠本輪輸入判定是否實唱，因此獨立列出，不混進可判讀案提高或降低分類成績。

長句的完整參考分組符合數兩者均為 0/20。這不是「語意準確率為零」：參考分組只有本輪自製的一組，沒有母語盲審，部分不同分組可能合理。但原始回覆也實際出現大量逐詞過切、只切第一個字、把對唱角色落單等問題，不能僅因文字拼接守恆就接受。便宜的純標點研究對照為 5/20 完全符合參考；本輪沒有證明模型優於它。

## 方法與固定條件

每語系 12 案：4 個製作資訊、4 個實唱保留案（其中 1 個同字歧義）、4 個長句。繁中、簡中、英、日、韓輪流執行；兩模型使用相同輸入、prompt、tokenizer 預檢與驗證器。題型、作者意圖、參考分組、時間與來源 id 不送模型，改用 opaque occurrence id；相同文字不合併。這是相關性高的小型診斷集，沒有新建經母語審查的獨立驗收集，不能外推實際 provider 精度或語言優劣排名。

主機為 Ryzen 7 7700、8 核／16 邏輯執行緒、63.16 GiB RAM。使用 [llama.cpp b11669](https://github.com/ggml-org/llama.cpp/releases/tag/b11669)，commit `620d2225cc436ab0b001e3200e590e3b286ef9ab` 的官方 Windows x64 CPU binary；生成與 prefill 都是 4 threads、單 slot、單模型、`-ngl 0`、offline、無 Web UI、loopback 驗證、不 thinking、不 context shift、不 prompt cache reuse。權重採 Unsloth 量化，與 Qwen 官方原始權重須區分。

使用 greedy（temperature 0、seed 117）及結構化輸出，context 4096、輸出預留 512；實測每請求輸入 483–1013 tokens，2B 輸出 59–123、4B 輸出 41–65，cache tokens 全部為 0。這是本輪固定配置，不宣稱已找到模型最佳 sampling／prompt／量化設定。

整體 2B 接受 52／60、拒收 8／60；4B 接受 50／60、拒收 10／60。拒收全是 `detached-role`，沒有請求逾時、截斷或缺測。接受僅指通過結構／範圍／保真驗證，不能當作品質通過率。兩者各有 15／20 個短 credits 被多餘切開，例如把 `作詞：` 與姓名分開。

2B 在接受的長句分組選出 50 個邊界，其中 9 個與 35 個參考邊界相同；4B 選出 45 個，其中 8 個相同。純標點對照選出 14 個，14 個均與參考相同，但漏掉其他 21 個。這些是「參考邊界符合」而非人工語意評分；失敗分組以未新增邊界計入，不將它們刪掉。

具體失敗與限制：

- 繁簡中：2B 的無標點繁中行切成 `當｜街燈｜一盞｜一盞｜熄滅｜我｜…`；4B 的簡中同行只切出 `当｜…`。兩者沒有穩定找到子句。
- 英文：兩者均有 `When｜the｜last｜train｜crosses｜the｜river, …`。合法詞界不能替代語意分組。
- 日文：可見 `君が｜【…】と言ったから｜手を｜握り、｜…`，引文保留但修飾／動詞依附仍被過切。
- 韓文：可見 `네가｜【…】｜라고｜말해서｜손을｜잡고,｜…`，字形安全仍不代表語尾依附正確。
- 對唱：4B 的五個純對唱及五個混語對唱均因角色標籤落單拒收；2B 在其中八個拒收，其餘也不能因保留整句就視為理解角色。
- 可合理的替代例：4B 把繁中引文行分為 `你說【別害怕，夜再深也有星光】｜我便握緊你的手，沿著河走到天亮。`，與三段參考不同，但不能單憑 exact 不同判成不自然。這類需獨立人工判讀，本輪沒有代稱母語驗收。

工作集含共享／檔案映射頁面，private bytes 是私有 commit；兩者不能相加當成實體 RAM。保守停止線用 `max(private, working set)` 加 runner RSS 與 sampler 用量，可能重複計共享頁，只用來保守停止，不宣稱精確系統新增 RAM。

2B／4B 取樣各 2879／4571 點，實際間隔中位數 127／126 ms，p95 都是 143 ms，最大 194／196 ms；private peak 仍可能漏掉短尖峰，工作集另取程序 high-water counter。監測本身使用 63.500／85.859 CPU 秒、約 90 MiB 等級工作集，不能忽略。整個 runner 的 CPU 累計亦在原始數據，不拿包含資產 SHA 校驗的累計冒充純推論。

這是同一台正在使用的 Windows 主機，各模型各一次正式批次，沒有隔離全部背景負載；2B 執行期間曾有短暫的聚焦測試，4B 無對應重跑。數字作本機觀測，不聲稱嚴格專用主機效能榜。權重在載入前已讀取驗 SHA，所以 process-cold 不是 disk-cold。沒有清 OS cache、電力、GPU／OBS 共用、8／16 GiB 主機或長空閒釋放測試；末次完成後短暫樣本仍持有大部分記憶體，程序退出已另行核對。

## 診斷、故障與限制遵守

正式 120 案之後，同一句 `Stay with me (oh, don't go) stay with me OH OH` 各模型做四次對照：原 schema、反轉 kind／breakIds／reasonCodes 的 enum 順序、JSON-only、無 response_format。四次的 input／opaque id／prompt 都相同，另外存檔，不混進正式品質或成本表。

兩模型在前兩種 schema 下回覆相同：2B 仍標 credit-candidate，4B 標 lyric，均選前六個詞界；JSON-only 與無約束則都列出全部八個詞界，被 `break-list` 拒收。這削弱「只是 enum 順序選第一項」的解釋，但不能由單一英文案例排除其他 prompt／greedy／量化／runtime 影響，更不能斷言模型家族本身不具能力。本輪沒有中途改 prompt、挑成功重跑或用診斷取代正式失敗。

原始全局推論時鐘從第一次載入起，到最後診斷結束共 1209.414 秒，約 20.16 分鐘，小於 45 分鐘，包含接續修復的間隔，沒有重設。正式與診斷共 128 次，沒有重複下載、GPU、30 秒請求或 8 GiB 停止線違規。

保留的非模型故障：

1. 啟動前第二次驗 SHA 用單次讀檔，4B 超過 Node 2 GiB buffer 上限；改串流，原失敗留存，當時尚未推論。
2. 2B 60 案完成後，收尾只看 exitCode，把 signal 退出誤判仍存活；核對 PID 已不存在，保留原 lifecycle 與獨立 recovered／exit-check 收據。補真 child 退出測試後只接續 4B，不重跑 2B，原全局時鐘不變。
3. 第一次 export 發生於診斷仍在寫入時，因 4B 診斷目錄尚未建立而拒絕；錯誤 log 保留，export 改為依完成收據辨識 in-progress，最終在八次完成後重新產出。

128 次 accepted／fallback 的最終 parts 均須逐碼拼接等於原文，hidden 永遠 false；時間不送模型、不從文字推算，也沒有時間寫回路徑。對唱、和聲、重複、引號、emoji、組合字元及分解 Jamo 都由原範圍保留。這是研究輸出保真，不是新產品處理路徑的驗收。

## 後續判斷與驗證

本輪結案為「CPU 可在預算內跑完；分類 4B 有研究價值；此語意拆句配置未達採用證據」。不增加第三個模型、微調或新 runtime，也不接產品。

若後續另外核准研究，先將 credits 與長句排序拆成獨立任務，針對候選複製／過切設計更窄的輸出，再凍結真正獨立且經母語審查的測試集。明確格式的 credits 先比較擴充規則；4B 是否值得約 4.4 GiB 工作集與約 10 秒單行 CPU wall 成本，必須看增益，不能只因分類比 2B 好就採用。相同文字是否實唱仍需人／來源證據，不能由模型自報信心授權刪詞。

研究契約、計分與真 child lifecycle 共 27 tests 通過；三個受測模組 coverage 為 statements 97.10%、branches 95.32%、functions 98.43%、lines 98.36%。這不是 runner 每條 CLI／網路錯誤分支的完整 coverage。最終格式、Markdown、收據／原文／模型 hash 與保護檔核對另留 verification 收據；沒有以產品 build／OBS 或母語聽辨當作已驗證事項。
