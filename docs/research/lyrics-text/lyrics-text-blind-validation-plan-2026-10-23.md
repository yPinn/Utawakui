# 歌詞來源合併塊：文字分段盲測計畫

本輪先提出驗證設計與成本，不建立正式盲測答案、不執行推論。基線固定為[前輪 C 的完整左右預覽與 E 的獨立分類](lyrics-text-qwen-ablation-2026-10-23.md)，使用既有 Qwen3.5 4B Q4_K_M、原 prompt／schema／候選產生器與驗證器，沒有新增產品流程。

## 要回答的問題

使用者描述的來源情境是歌詞平台上傳的文字：一個帶時間的來源塊可能收進不同句歌詞，空白也可能代替句間標點。這是本批案例的問題假設，不是已量化的平台人工上傳比例或合併率。

研究目標是讓同一曲目的來源塊得到兩種互相配合的文字判斷：其中有沒有多個可獨立閱讀的歌詞子句，以及整塊文字是否像製作署名、實唱或資訊不足。空白、長句與時間區間都是排查入口，不能各自作為必須拆段的答案。

必須區分三個層次：

1. 來源塊：provider 原有的一行或 cue，以及原始文字、起訖與身分。
2. 文字子段：來源塊內可接受的語意分組。可有多種拆法，也可保留整塊；不改來源塊。
3. 演唱時間／曲式段落：子段何時唱、是否拖音或間奏、是否主歌／副歌。這些需要另有聲學或人工證據，本輪不由空白或長區間推定。

即使判定一塊含三句歌詞，也只輸出來源切片的分組建議，不建立三個新時間區間、不平均分攤秒數，也不把顯示頁面當成新的 canonical 歌詞行。模板容量與字級不送入模型，與文字可接受性分開。

## 新案例矩陣

繁中、簡中、英文、日文、韓文各 20 個新 occurrence，共 100 個；每語系 12 個拆句案例、8 個分類案例。各語系獨立寫自然句，不將同一中文原型逐語翻譯後視為五份獨立證據。這批是人工合成、仿來源結構的測試，沒有存取私人曲目或歌詞平台；真實 provider 泛化仍待後續獨立驗證。

正式案例與答案尚未製作。下表凍結的是題型與數量，不是已完成母語審查的測試集。

| 拆句題型                               | 每語系數量 | 要查的失敗                                                                               |
| -------------------------------------- | ---------- | ---------------------------------------------------------------------------------------- |
| M1：兩至三個意思合在一塊，三個空白版本 | 3          | 同一內容各自製作單空白、重複／全形空白或 tab、無明顯分隔的 fixture；不把每個空白都當斷點 |
| M2：三至四個子句合併，弱標點或混合分隔 | 1          | 不能只切第一刀便認為完整解決合併塊                                                       |
| N1：長但仍是一個完整意思               | 1          | 長時間、長字串或多個空白不能強迫過切                                                     |
| N2：短句與語氣／重複實唱               | 1          | 正確選零斷點，不刪 OH、重複詞或全大寫                                                    |
| D1：明示雙人聲部、輪替接唱             | 1          | 保持標籤與唱詞相連，優先可理解的聲部交接                                                 |
| D2：無標籤接唱或句內混語               | 1          | 不憑語言切換猜角色，不憑文字宣稱已辨識兩個歌手                                           |
| H1：主唱嵌入括號和聲                   | 1          | 不拆散括號內容，不省略和聲，不把和聲強制當下一個時間段                                   |
| A1：從屬／修飾依附                     | 1          | 日文重點為「連體形＋とき／こと／もの／ため」等實際依附；其他語系使用各自自然依附形式     |
| A2：附屬助詞／助動或固定詞組           | 1          | 日文檢查格助詞、引用＋と、ている／てしまう等依附；其他語系檢查詞組、縮約與語尾           |
| Q1：長引文或引用製作字樣的實唱         | 1          | 區別引號範圍、語意邊界與製作資訊，不因標點表面整齊便亂切                                 |
| 合計                                   | 12         | 五語系共 60 案                                                                           |

M1 三個版本是三份新的不可變 fixture，不是對真實來源作正規化；來源空白逐碼保留。它們只算一個語意家族，因此每語系拆句有 12 個輸入、10 個內容家族。空白對照另報成對結果，不能當三個獨立樣本提高樣本量。

每語系的 M1／M2／D／H 至少一案同時含另一種指定語言；標點分配涵蓋 `【】`、`「」`、ASCII／彎引號與詞內 apostrophe。英文不刪正常詞間空白來製造不自然主測題；其「無明顯分隔」版保留詞內及詞間結構，只移除句間額外空白／標點。Unicode 組合字與韓文 Jamo 至少各一案，避免只驗普通字元。

| 分類題型                                    | 每語系數量 | 預先標註方式                                                                         |
| ------------------------------------------- | ---------- | ------------------------------------------------------------------------------------ |
| 明確製作署名、括號／無冒號署名              | 2          | apparent credit-candidate，仍完整保留；不將「看似署名」當成未實唱證據                |
| 聲部／演唱者標記與唱詞                      | 1          | lyric；包括具名對唱，不能把 cast 當應刪資訊                                          |
| 和聲／合唱與括號唱詞                        | 1          | lyric；保留角色及內容                                                                |
| 句中引用製作字樣的實唱                      | 1          | lyric；有足夠文字上下文可辨識的負例                                                  |
| 同一來源塊混有署名與實唱                    | 1          | mixed，對目前只有三種 kind 的 E，預期 ambiguous；不允許整塊當成可省略製作資訊        |
| 原文完全相同、作者用途不同的一對 occurrence | 2          | 只提供相同可見文字；隱藏意圖一為署名、一為實唱，列不可辨識組，不強迫模型猜中秘密答案 |
| 合計                                        | 8          | 五語系共 40 案                                                                       |

分類主表分開列 10 個署名、15 個可辨識實唱負例、5 個混合塊，以及 5 對／10 occurrence 的同字歧義。歧義組不混入可辨識 precision／recall；列 kind 分布、棄權與配對一致性。相同輸入得到相同候選不是成功辨識隱藏意圖；候選落在實唱 occurrence 是需保留的風險案例。credit-candidate 的語義本來就是假設，不能為追求棄權分數而事後改標準，任何 kind 都不授權刪除。

## 同一來源塊與時間的控制

主測為 60 次 C 拆句、40 次 E 分類。固定再選每語系四個來源塊做兩項任務：M1 的單空白版、H1、分類的對唱塊與混合塊。這 20 個來源塊主測已各跑一項，只補另一項，共增加 20 次，總計 120 次請求：C 70 次、E 50 次。主測與共同子集分母分開，不重複灌入主品質分數。

共同子集檢查分類與拆句是否都保持原塊、角色和和聲，以及「混合塊」是否暴露 E 整行分類的能力邊界。E 不輸出局部署名範圍，C 也不替子段分類；本輪不將它們偷偷組成自動清理器。就算 C 分出署名與實唱，也不再追加逐片分類或自行隱藏某片。

每語系選 M1、M2、N1、H1，共 20 個主測來源塊，於評估器內各放短／長兩個合成區間，例如 8 秒與 32 秒。原版 fixture 從凍結起不變；對照版為獨立評估記錄，不回寫原時間。兩個時間版本重用相同文字結果，沒有新增模型請求，也不聲稱做了兩次獨立推論。

先以純文字完成分組審查，再獨立檢查區間資訊。時間只在 evaluator 持有、從模型 payload 排除，長區間不得提高拆句正確性分數：N1 即使 32 秒仍可是一句拖長；M2 即使 8 秒也可能含多句。沒有音訊不能判定是哪一種。檢查原文字／原起訖 hash 不變、模型與結果沒有新時間欄位；無法證明真實演唱邊界時維持 unknown，不生成合成子時間。

## 盲測與多種合理拆法

1. 先凍結 C／E prompt、原 candidate generator、驗證器、模型／runtime SHA、樣本矩陣與預算，才製作新案例。舊 60 案與上一輪 35 案均不可改名重用；few-shot 不加新測試題。繁簡中不僅作字形互換。
2. 題目作者與至少兩名具相應語言能力的審查者分工。審查者先看原文，獨立標出零到六個切點的合理完整分組、不可切依附／角色／和聲範圍、可選切點與資訊不足；先不看候選、模型輸出、長短時間或組別。
3. 審查者在看輸出前協調多個可接受分組；有爭議時交第三人裁決，仍無法決定就保留 unresolved。每語系至少十個拆句輸入完成可評標註才稱具備正式品質驗證條件；未達就不啟動模型，報審查未完成。兩份同來源空白版本不替代獨立語言審查。
4. 凍結 answer manifest 與輸入 manifest 的獨立 SHA。模型只讀去標籤的輸入，以隨機 opaque ID、固定隨機次序執行；題型、作者意圖、pair id、時間、參考分組及不可切範圍均不進 prompt。答案在生成完成後才交評分程序。
5. 預先標註完才產生候選與檢查覆蓋，保留「沒有任何合理分組可達成」的案例。不得看候選後移動答案，也不得看失敗後補候選、改 prompt 或換成功題。需要修正時保留本版，另提下一版，原盲測退為開發集。
6. 生成結果交語言審查時，隱去方法名稱、原始 kind 理由及先前成績，以隨機編號評分。未列入預設答案但審查認為合理的輸出，留為事後補充裁決；不回改主成績，另報擴充答案的敏感度。

正式新題尚未寫好、母語審查人力也未安排；不能把同一代理自行寫題、自行打分稱成獨立母語盲測。若只能完成這種流程，就標為新合成留出診斷，人工品質欄位維持 pending，不宣稱真盲測通過。

每案可存數個完整分組，輸出符合其中任一組就算可接受；不得把不同答案的切點取聯集後隨意組合。不可切違規另計，語法合法不等於語意可接受。空白位置可由審查者預先允許等價切點區域，但輸出 parts 始終按原字串 slice，不能 trim、合併空白、繁簡轉換或改 Unicode。

另以同一候選與同一多答案評分，做不切與固定標點優先的零模型對照；它們不新增模型請求，也不代表現有模板語意品質。統計同時列輸入數及家族數，不用三個空白版本或同字 pair 假裝獨立樣本；本批每語系僅 12 個拆句輸入，不作語言排名或顯著性承諾。

若每語系至少 10／12 可評拆句達預先接受分組、較兩種零模型對照有改善，且沒有保真／角色／和聲遺失與新的可辨識實唱誤標，才值得提出下一步研究；這是本批研究判讀線，不是產品採用 gate。個別語系未達就分開報告，沒有用總平均抵銷日文或韓文退步。不可達成、拒收與缺測均不能靠事後排除來過線。任何人工審查未完成，都不能宣稱此線已過。

## 預估成本與停止條件

只使用現有 4B Q4_K_M 及 CPU runtime，不下載、不裝新環境。沿用四 inference／prefill threads、單模型／單 slot、無 GPU／thinking／prompt cache、4096 context 含 512 output 預留，原目標分析上限 2000 UTF-16、最多六個選中切點。主題以二至四個可讀子句為主；超限長塊仍需列出支援缺口，不能截斷後冒稱已完整分析。

完整左右預覽會隨文字與候選數快速膨脹。正式生成前逐請求用實際 tokenizer 檢查完整 prompt＋512 是否不超過 4096；超限就列 preflight-skip、保留原塊與主分母，不縮減候選、不裁目標、不偷偷分窗。設計時可規劃不同長度帶，凍結後不可為了擠進 context 換掉失敗題。

不做雲端 API，所以沒有此輪 API 用量費；電力、人工單價與 OBS 同時運行影響未估價、未測。模型 CPU 秒另按實測報告，不拿 wall×四執行緒當已耗 CPU。

任一原文／時間保真違規、輸入或驗證器版本不符、程序存活異常或停止監測失效均停下並保留收據；單次超時須終止 native 推論程序，整批停止，不自動重啟補跑。RAM 達線、全局到時、磁碟 reserve 不足同樣停止。一般非法選點或模型回覆 schema 不符仍記該案拒收／回退並繼續既有固定 schedule，不能自動重寫再問；若整批已停，所有剩餘缺測如實列出。
