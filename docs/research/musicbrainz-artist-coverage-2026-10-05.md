# MusicBrainz artist 覆蓋率與名稱來源實測

日期：2026-10-05

## 研究問題

[ADR 0022](../adr/0022-artist-identity-and-organization.md) 採用 MusicBrainz 作為 artist identity 的外部來源。實作前需要回答三件事：

1. 以實際曲庫的演出者來說，MusicBrainz artist 搜尋的命中率有多少？
2. 只靠名稱完全吻合，能不能安全地連到正確的 artist？
3. 曲庫裡 `Kenshi Yonezu` 這類羅馬拼音名稱，是 yt-dlp 語系造成的，還是來源資料本身就是這樣？

本研究只保存彙總數字與知名藝人範例；逐位演出者的完整結果留在本機，不進 repo。

## 方法

- 曲庫：一份 269 首的實際曲庫，268 首來自 provider 匯入（以 YT Music 專輯為主），1 首本機檔案。
- 對象：曲庫 `artist` 欄位以逗號拆出的 54 位 credited 演出者，其中 21 位符合 ADR 0022 sidebar 收錄條件（擁有專輯或至少 2 首）。
- MusicBrainz：官方 WS2 `artist` 搜尋，查詢字串為完整名稱，每位一次 request、間隔 1.1 秒、可辨識的 User-Agent。比對時以 NFKC＋大小寫折疊，檢查 name、sort name 與 aliases 是否完全吻合。
- 語系：用 App 內建的 yt-dlp，以 `youtube:lang=ja`／`zh-TW`／`en` 分別取得 3 首 YT Music 曲目的 metadata。

## 結果

### 覆蓋率

| 範圍            | 演出者數 | 命中（名稱或 alias 完全吻合） | 以 alias 命中 | 多個同分完全吻合 |
| --------------- | -------- | ----------------------------- | ------------- | ---------------- |
| 全部 credited   | 54       | 44（81%）                     | 10            | 1                |
| Sidebar 收錄者  | 21       | 18（86%）                     | 3             | 1                |
| 只有 1 首合作曲 | 33       | 26（79%）                     | 7             | 0                |

所有 54 次 request 都回 HTTP 200，沒有遇到 503 或 429。

沒命中的主要有三類：中國饒舌圈的團體與客演、在 credit 裡寫成「原文名＋英文名」的雙語形式（例如 `盧廣仲 (Crowd Lu)`，MusicBrainz 的 name 只是其中一種寫法），以及小眾合作者。其中一個未命中的團體在曲庫裡有 21 首，是曲數第二多的演出者，所以「沒收錄的藝人靠本機規則與手動處理」不是邊緣情況。

### Alias 命中的名稱都正確，並提供原文名稱

10 筆 alias 命中全部指向正確的 artist，而且 MusicBrainz 的 name 正好是原文寫法：

| 曲庫 credit   | MusicBrainz name         |
| ------------- | ------------------------ |
| Kenshi Yonezu | 米津玄師                 |
| Rainie Yang   | 楊丞琳                   |
| Hatsune Miku  | 初音ミク                 |
| Masaki Suda   | 菅田将暉                 |
| ZUTOMAYO      | ずっと真夜中でいいのに。 |

這支持 ADR 0022「查到時以 MusicBrainz name 為顯示名稱」的決定。但像 `ZUTOMAYO` 這種使用者可能更習慣縮寫的情況，也說明手動覆寫是必要的。

曲庫裡唯一的跨寫法重複（同一人在同一 credit 裡以兩種寫法出現）也解得開：兩種寫法都連到同一個 MBID，一個以 name 命中、一個以 alias 命中。這是日後以 MBID 自動合併的直接證據。

### 只靠名稱完全吻合會連到錯的 artist

名稱完全吻合不代表是同一位。至少 3 筆是同名的其他 artist：

- 一位日本歌手的搜尋結果有兩個同分的完全吻合，排第一的是只「出現在另一位藝人曲目」的同名者。
- 一位小寫名稱的歌手連到另一位歌手的別名。
- 一位華語歌手連到同名的瑞典歌手。

這三筆的名稱本身和曲庫寫法相同，所以就算連錯，顯示名稱也幾乎不變（最多只有大小寫差異）。但如果連錯的 artist 被拿去合併、或取得它的 aliases，就會把不相干的名稱帶進來。ADR 0022 第 3 條「搜尋＋至少一首錄音佐證才自動連結」是必要的，不能省略。

### 名稱不受 yt-dlp 語系影響

三首曲目在 `ja`／`zh-TW`／`en` 三種語系下，`artists`、`artist`、`uploader` 與 `track` 完全相同。羅馬拼音的 `Kenshi Yonezu` 是發行方在 YouTube 登記的名稱，同一首歌的曲名也是羅馬拼音。因此：

- 跨寫法重複不是使用者語系造成的，而是不同發行、不同廠牌的登記方式不同。
- 切換語系不能修正名稱；要取得原文名稱，只能靠 MusicBrainz 或手動覆寫。

另一個觀察：上傳者頻道名常同時帶兩種寫法，例如 `周杰倫 Jay Chou`、`Kenshi Yonezu 米津玄師`、`Yitai Wang - Topic`（對應 王以太）。這些可以當作本機的 alias 線索，但頻道名格式不固定，只能用於建議，不能自動合併。

本次只測了 `lang` extractor 參數，沒有測不同國家 IP；地區差異不在本研究範圍。

## 對 ADR 0022 的影響

| 項目             | 結論                                                                             |
| ---------------- | -------------------------------------------------------------------------------- |
| MusicBrainz 採用 | 覆蓋率足以作為第一來源；約 15–20% 的演出者仍需本機規則與手動處理                 |
| 顯示名稱         | Alias 命中能提供原文名稱，維持「MusicBrainz name 優先、可手動覆寫」              |
| 自動連結條件     | 名稱完全吻合不足以連結；必須保留錄音佐證，或在顯示名稱以外的用途前要求使用者確認 |
| 請求成本         | 每位演出者 1 次搜尋，加上佐證需要的 1 次 recording 查詢；21 位約 1 分鐘內完成    |
| 語系             | 不需要為了名稱而切換 yt-dlp 語系                                                 |
| 頻道名           | 可列為 Tier B 的建議來源，不作自動合併依據                                       |
