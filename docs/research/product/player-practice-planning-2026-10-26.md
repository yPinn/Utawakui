## 目前實作核對與分類補正

- `usePlayer` 在新曲、重新開始、恢復與 repeat-one wrap 會重設音高／速度及導唱開關；一般 pause／resume 不建立新播放 revision。來源 URL 更新另有保留現行音訊控制的同步路徑，不能混同換歌。
- `useAudioPreferencesPersistence` 保存 master／capture 音量與兩個導唱 level。它監看的是目前 player state，因此若直接把歌曲導唱比例寫進相同 state，會污染 machine preferences。第一版歌曲設定不保存導唱比例與擷取配置。
- 場次契約與 production controller 已有 `manual`，前端有 `PerformanceSessionManualItemForm`，preload／Main 也有 append-manual intent。它以明確開始／完成管理外部音訊或自行伴奏，沒有 audio clock／假媒體檔；不是尚缺的新資料模型。
- 場次 confirmed start 已經由 Main 接到 `sessionHistoryService.observePerformance`；與真實 OBS 環境的驗收是另一件事。前輪將 history commit 列待實作的說法需補正。
- 現有 `useLyricsTimingEditor` 已能編輯句內邊界、undo 及產生 T2 文件；已有來源 offset。波形與人工確認應補在這條路徑，不另建歌詞 editor。

以上只確認程式／契約與入口存在，未在本輪操作正式 App 或 OBS。前輪日期報告與數據保留，新發現由本文件及現行入口補正。

## 1. 逐曲演唱設定

### 目的與第一版範圍

讓同一首曲目再次載入時，套用使用者明確保存的演唱設定；目前滑桿調整仍是本次操作，不自動改寫已保存歌曲設定。

| 欄位                              | 第一版保存 | 行為                                                                                   |
| --------------------------------- | ---------- | -------------------------------------------------------------------------------------- |
| Key／移調                         | 是         | 沿用現行 -12～+12 半音與整數正規化。                                                   |
| 音高微調                          | 是         | 沿用現行 -50～+50 cents 與整數正規化；與 Key 分欄。                                    |
| 速度                              | 是         | 沿用現行 0.5～1.5 倍與控制步階。                                                       |
| 監聽導唱開關                      | 是         | 只控制已有分離結果的監聽導唱；沒有結果時呈現不可用，不自動分離。                       |
| 監聽／擷取導唱比例                | 否         | 維持機器校準 owner；逐曲比例須先定義獨立 effective layer，不能讓套用觸發全域偏好寫回。 |
| Master／擷取音量、mute、裝置、BGM | 否         | 維持現有 machine preferences／BGM plan。                                               |
| 歌詞來源／offset、A–B、播放位置   | 否         | 分別由歌詞、練習與播放恢復 owner 管理。                                                |

數值以實作時的 canonical registry 為準；本表記錄當輪讀到的範圍，不在新模組複製一份常數。擷取導唱不因套用歌曲設定而開啟。

### 作用域與保存

- 第一版只保存每個 library 內、canonical track 的一份設定；不以歌名、藝人或 work id 合併不同錄音／版本。同曲在多個歌單仍共用這份設定。
- 建議 Main-owned sidecar 放在該 track 目錄，具 schema version／revision；檔名與 IPC 名稱在實作契約決定。Renderer 只送 track id、expected revision 與固定欄位，不送 path、URL、hash 或 model。
- 沒有 sidecar 代表使用 canonical defaults；草稿欄位缺失、非法值與未支援版本須有明確讀取結果，不能把 I/O 失敗當成「沒有設定」。
- 保存是明確動作，取已實際套用的值；等待中的 DSP 請求或套用失敗的目標值不可冒充目前設定。保存成功後更新同一 revision，失敗保留可重試內容。
- 「重設目前控制」只回 canonical defaults，不刪已保存設定；「套用歌曲設定」與「移除歌曲設定」各有明確語意。移除持久化設定不突然改變正在唱的控制值。
- 第一版不保存 occurrence override。安排內臨時修改只影響這次播放；未來若加入場次覆寫，優先序為 canonical defaults → 歌曲設定 → 明確 occurrence override → 本次臨時調整，且不得反向寫回前一層。

### 播放生命週期

| 事件                                       | 擬議行為                                                                                |
| ------------------------------------------ | --------------------------------------------------------------------------------------- |
| 明確載入新曲／開始另一個 occurrence        | 清除前次臨時調整，先解析並套用該曲設定，再准許開始。                                    |
| Pause／resume、buffering、一般 seek        | 保留目前臨時值與播放身份。                                                              |
| 同次播放的 repeat-one wrap／A–B 重播       | 保留臨時值，不重新讀檔或重設。這會改變目前 repeat-one wrap 的 reset，須有回歸。         |
| 同曲明確「重新開始」                       | 先停用區段循環，再回到媒體 0 秒並重新套用已存設定；與區段重播分開。                     |
| 原曲／分離結果切換、metadata 導致 URL 更新 | 沿用現行 library sync，保留本次控制，不視為新曲。                                       |
| App 重啟恢復                               | 解析歌曲已保存設定，仍保持 paused；不恢復未保存臨時值，也不把設定塞進 resume snapshot。 |
| 切換 library／刪曲／取消 pending start     | 舊請求失效；晚回的讀取、DSP 完成與保存不得套到新曲庫或新播放。                          |

所有跨 await 都驗 library scope／epoch、track id、start request 與播放 revision。不能只比 path 或 track id，以免 A→B→A 換庫或同曲兩次開始混用。讀取／DSP 失敗停在可辨識錯誤，提供重試或明確按預設播放；不得在錯誤 Key 下無提示開唱。

目前部分 DSP setter 捕捉錯誤後以 fulfilled Promise 結束，實作前須補明確套用結果；不能把 `await` 返回直接視為設定成功。主／擷取路徑任一失敗時應說明哪條路徑不可用，沿用既有 fail-closed 規則，不假造成功狀態。

### 入口與驗收

沿用歌曲情境與演唱控制，提供保存／套用／移除命令；不在 Settings 建每首歌的清單，不另造第二組滑桿。具體版位等待既有視覺規範。

驗收 P01–P08：無設定的預設、明確保存與重啟套用、pause／同次循環保留臨時值、不同 occurrence 重套、來源切換不重套、缺分離不自動處理、讀取／DSP／CAS 失敗，以及切曲／換庫／取消期間的晚回防線。另確認 machine preferences bytes、擷取裝置與導唱 level 不因歌曲套用而變動。

## 2. 區段練習

### 第一版行為

- 只使用既有主播放器與音訊圖。A、B 是原始媒體時間，與歌詞 offset、目前 tempo 無關；變速只改實際播放速度，不改端點。
- 必須有可 seek、有限 duration 的本機曲目。A／B 有限且滿足 0 ≤ A < B ≤ duration；最小區間暫以 500ms 作原型候選，須量測後確認，不宣稱任意短 loop。
- 「設 A」「設 B」只更新標記；缺任一端點或驗證失敗時不能啟用。編輯已啟用區間先停用循環，再由明確動作重新啟用，避免拖曳突然 seek。
- 啟用不自動從 paused 開始播放。下次 play 時若位置不在區間內，先移到 A；播放中啟用則按明確區間套用行為處理。
- 重播前等待提供 0／1／2／4 秒的原型選項，預設 0；等待按 wall time 計，不受歌曲倍速影響。第一版只有視覺倒數，沒有新 click track、預備拍音訊或第二個時鐘權威。
- 等待期間 media 暫停於 A；到期只送既有 play intent。Pause、stop、換曲、清除／停用區間均撤銷 pending start，晚到 timer 不可恢復播放。
- User seek 在 A–B 內保留循環；seek 到外側即停用循環、保留標記，不把使用者拉回。換曲／換庫清除標記；App 重啟不恢復啟用狀態。

### Transport、歷史與 BGM

- HTML audio 是唯一時間權威；邊界 controller 唯讀採樣實際位置，再經 `usePlayer` 執行 pause／seek／play，不自行累加歌曲時間，不直接另建 Audio。
- A–B active 時由既有 transport 仲裁決定區段返回，普通 repeat／shuffle 不同時介入。原 playback mode 的還原不得蓋過使用者後續選擇；第一版可在循環期間停用衝突控制。
- B 接近／等於 EOF 時，必須由同一 terminal decision 在一般 Queue 前進之前判定練習重播；不能先完成下一首，再從另一個 ended listener 拉回。需要在現有 transport 做明確切口，未驗證前不開放 EOF 區間。
- 區段重播保持同一次 playback revision，不呼叫「重新開始整首」；不增加場次開始／完成、章節或每輪播放次數。最近播放仍按既有實際播放 qualification，每次 logical playback 至多一次；已發生紀錄不回溯刪除。
- 已由演出安排持有播放時，第一版不啟用 A–B；使用者須明確離開該次安排控制再練習，不能在背後把 occurrence 改為完成或中止。
- 倒數是練習內部間隔，BGM 不能每輪插入；沿用 handoff coordinator 的互斥 lease。明確結束練習後才按既有政策交接。曲目試聽仍沿用自己的低優先 lane，不加入另一套循環。
- Output／提詞器繼續投影實際媒體位置與 seek，不能一邊 loop 一邊發布假連續時間；不自動啟用公開輸出。

### 邊界品質與驗收

`timeupdate` 不能單獨作為細區間品質承諾；原型需量測前景、背景／最小化、變速與負載下的 overshoot。可用既有實際 clock 採樣與後備事件，不能以 rAF 次數冒充 audio 精度；本規格不承諾 sample-accurate／無縫 loop。

驗收 L01–L09：端點／duration 驗證、paused 啟用、內外 seek、倍速不改端點、等待取消、EOF 單一仲裁、repeat／Queue 隔離、BGM gap 不插播，以及換曲／換庫／背景狀態下不誤播。第一版不含持久化書籤、筆記、曲式自動分段或逐輪導唱漸退。

## 3. 歌詞對時確認

### 對時確認的目的與範圍

在既有曲庫歌詞編輯頁補上可跳轉的音訊波形、來源時間標記與人工確認，服務使用者檢查和修正；演唱閱讀頁仍保持現場職責。不新增來源搜尋器、ASR 或第二份歌詞文件。

- 第一版波形以 canonical 原始音訊為基準，不為顯示波形而自動分離。人聲波形只在後續明確決定且已有結果時評估。
- 顯示句級起點／有效終點；已有可信 T2 才顯示對應細時間。T1 的估計結束或 T1+ 不冒稱原生逐字資料，不以波形推論未聽辨的邊界。
- 點波形可試播 seek，拖曳標記擴充同一 editor 的 timing draft；保存／取消／undo 沿用原 owner。現行工具主要處理句內逐字邊界，句級起點／終點拖曳仍需擴充草稿與 Main commit 契約，不能宣稱已具備。沒有合法終點或句內分段能力時，保留現有降級，不為可拖曳而偽造 T2。
- 波形分析採有界衍生資料。先比較 browser decode 與 Main 派生方案的峰值記憶體、長曲成本、取消、seek 與快取；不先假設一定需要 FFmpeg，也不為此隱式準備工具／runtime。
- Main 方案只提供有界摘要及 opaque identity，不將完整 PCM、任意 path 或 decoder 參數交給 renderer；快取與來源修訂綁定，失效不影響原始媒體或歌詞。

### 人工確認與失效

「來源對時已確認」只代表使用者對當下文件作了明確確認，不代表全曲品質、OBS 裝置同步或模型可信度已由系統證明。第一版以所選 T1／T2 來源的整體對時為範圍；不將未計時 T0 標成已對時，也不把 T1+ 估計升格為可信 T2。

確認資料與歌詞原文、timing 及 waveform cache 分開保存，由 Main 導出音源身份、來源 fingerprint／document id、timing revision、有效 offset 與確認範圍。Renderer 只送 track id、來源 session id、expected revision 與確認 intent，時間戳由 Main 產生。

| 變更                                    | 確認狀態                                                     |
| --------------------------------------- | ------------------------------------------------------------ |
| 修改原文、時間邊界或 offset／換另一來源 | 原確認不適用新版本；各來源不能共用一個已確認旗標。           |
| 更換音源或未能證明等價的檔案修訂        | 標需重確認；不只看檔名或 track id。                          |
| 封面／藝人顯示名、讀音、文字顯示選項    | 不改 canonical timing，維持確認。                            |
| Key／速度或導唱開關                     | 不改原始媒體座標，維持來源確認；不據此宣稱設備延遲也已校準。 |
| 重新產生分離或 waveform cache           | Canonical 音源／timing 未變時維持確認；只更新衍生快取。      |
| 暫時開啟 T1+ 估計                       | 不用基礎來源的確認替估計背書；另顯示目前在看估計。           |

媒體 identity 應沿用 Main 驗證的修訂證據。若現有 hash 含 FLAC tags 等非音訊 bytes，第一版需明列保守失效；只有現行交易能證明音訊未變時才保留確認，不在 renderer 猜測等價。

先保存 timing／offset，再以 fresh revision 確認；確認寫入失敗時顯示「時間已保存、確認未保存」，保留重試，不還原已成功的校時。讀取錯誤與未確認分開。換曲／換來源／晚到回應、CAS 衝突與草稿取消不得替其他版本打勾。

### 驗收

驗收 T01–T09：T0／T1／T2／T1+ 區分、既有 editor 保存／取消、波形無新增時間權威、來源分開確認、時間／offset 變更失效、純顯示變更不失效、音源／tag 修訂政策、部分保存失敗，以及長曲／取消／快取與晚回身份防線。波形 UI 的視覺製作沿用現有設計定案節奏，不能用新功能搶先重建整頁。

## 4. 可自訂／全域快捷操作

先完成[輸入綁定契約](../../contracts/input-bindings.md)記錄的焦點、editable、modal 與快捷鍵重疊盤點。使用同一 bounded command registry 分派，不讓全域鍵、SMTC、手機與 PlayerBar 各自擁有 transport。

第一階段命令限播放／暫停、上一／下一首、Key 與歌詞 offset；裝置、擷取音量與任意 IPC 不提供自由綁定。App 內綁定與全域綁定分開啟用；全域預設不註冊普通字元鍵，使用者明確指定組合鍵。衝突／被 OS 占用要回報未生效，不以設定存檔成功冒充註冊成功。

修改採先驗證與嘗試註冊、成功才替換舊綁定；App 退出／停用時釋放，單一 instance 擁有註冊。重複鍵、長按、輸入法、modal 與不能執行的動作走既有權限／disabled 語意。設定只放命令綁定偏好，沒有第二套播放 UI。

驗收 K01–K04：註冊／更換／回復、OS 衝突、焦點與重複觸發、退出釋放與共用 transport。此項先有規格，仍未實作全域鍵。

## 5. 無伴奏演出：既有能力覆核

保留 `manual` 與現有 form／append／progress／Output 路徑，不再新建一種假媒體或平行 item type。先以現有 UI 驗開始、完成、中止、外部播放接手、BGM 交接、重啟恢復及封存／匯出資訊損失，確認文案能讓使用者辨識其用途。

目前 manual 沒有媒體 duration 或歌曲 clock。若之後確有定時結束需求，定時器只管理明確的演出進度，不偽裝成 HTML audio；必須另定 pause／背景／重啟語意，本輪不加入。OBS history 的 production 接線已存在，後續工作是實際連線與去重驗收。

驗收 M01–M03：實際新增入口、手動進度與單一 NP、BGM／歷史／封存邊界。本輪只核對程式／契約，未宣稱完成可見操作驗收。

## 6. 衍生音訊減量：研究方案

先固定目前四聲道 WAV 基線，再比較候選格式的容量、編碼耗時、冷暖載入、隨機 seek、CPU／RAM、變調品質及長時間聲道同步。通道順序必須仍為伴奏 L/R、導唱 L/R；synthetic channel identity／tone 可驗路由，不能代替自然音樂聽感。

測試需涵蓋短／長曲、不同 sample rate、純伴奏／有人聲與已有 DSP 路徑。資料與樣本範圍在執行前固定，保留全部失敗，不因單曲縮小就外推整庫。尚未選 codec、品質或壓縮比，也不以 KAREOKIE 的宣稱作本案預算。

若採用，先對新衍生結果 opt-in；原始素材不變。舊結果轉換需 staging、驗證、manifest 原子切換、回復、可取消及磁碟安全空間；當前播放／Queue 保護與既有容量清理政策保留。實驗 R01 通過品質與交易條件後，才另提遷移與預設政策。

## 7. Mic 電平驅動畫面：研究方案

先驗只讀輸入到強度摘要，不做人聲監聽、錄音或音訊混音。由使用者明確啟用與指定裝置；停用／裝置失效就停止輸入，不自動換另一支 Mic。音訊權限與生命週期不能借用公開輸出開關隱式開啟。

以相對電平／dBFS 包絡測安靜、環境噪聲、輕唱、強唱、短促爆音與削波；需靈敏度、噪聲門檻、平滑起落與輸出上限。只映射指定裝飾的幅度、密度或亮度，不改歌詞時間／可讀性。靜音、失訊與停用平滑回基準；reduced motion 可停用或降級。

先以本機單一視覺原型量測輸入到畫面的落後、誤觸發與操作成本；聲音大不代表唱得好，也不能推論是誰在唱。確認價值後才定 Output 支援模板、明確發布及低頻有界摘要的 transport，不傳原始 Mic 音訊。

實驗 R02 的退出條件：環境噪聲／伴奏串音無法控制、反應落後干擾演出，或顯著影響播放可靠性。未通過時保留為研究，不為畫面效果開放軟體監聽。

## 8. Mic 音準視覺化：研究方案

可重用經驗證的輸入生命週期，但與畫面強度用途分開驗收。依序做輸入音高、參考旋律與歌曲時間對照；前一段不足時不以總分掩蓋問題。

- 輸入：以已知音高、靜音、噪聲、滑音、低／高音與八度混淆測錯誤、可用覆蓋與延遲。沒有可信音高時顯示未知，不持續沿用上一音。
- 參考：有已存在且可用的人聲結果時先作小樣本對照；未取得分離能力時不隱式準備。合唱、和聲、混響與非主旋律段落要能拒判，不能把最強頻率當主唱真值。
- 對時：分開伴奏輸出、Mic 輸入與分析窗延遲；固定偏移校準不能掩蓋 jitter／drift。硬體／路由改變需重新評估。視覺顯示可接受的延後與演唱同步的容忍度需先量測。

實驗 R03 先產生音高線與可信度／未知區段，不產生唱功總分、成績比較或排行榜；也不提供人聲回放。模型／library 選型、資產下載與真實 Mic 測試在研究執行時另定，本輪未開始。
